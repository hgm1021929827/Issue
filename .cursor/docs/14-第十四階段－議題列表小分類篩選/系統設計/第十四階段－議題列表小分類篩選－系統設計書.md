# 一～二

改 `IssueListPage` Chip 資料來源為議題大分類底下的小分類。`GET /issues` 新增可選 `subCategoryId`。無 Schema 變更。首頁／專案列表不改 Chip。

# 三、流程

- `/issues` 載入大分類，名稱等於「議題」，否則「議題分類」；再 `GET /subCategories?majorCategoryId=`。
- Chip：「全部」＋小分類名稱（`sortOrder`）。外觀沿用既有 `.filters`／`.chip`。
- 「全部」→ `GET /issues`。選一小分類 → `GET /issues?subCategoryId=`。
- 未填 `subCategoryId` 的議題只在「全部」。無效 id 回空列表。

# 四、API

| 方法 | 路徑 | query | 說明 |
|------|------|-------|------|
| GET | `/issues` | `majorCategoryId?`（既有，首頁仍用）、`subCategoryId?`（本階段） | 兩者可同時（AND） |

回應契約不變。`GET /subCategories` 不改。

# 五～六

前端 `api.issues` 改物件參數 `{ majorCategoryId, subCategoryId }`。首頁只改呼叫形式，Chip 仍是大分類。
