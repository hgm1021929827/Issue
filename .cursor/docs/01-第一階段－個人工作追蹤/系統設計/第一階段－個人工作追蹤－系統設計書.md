# 一、系統架構

採**前後端分離**：

- **frontend：** React（Vite）SPA，埠 `5173`
- **backend：** ASP.NET Core 9 MVC（API Controller，回傳 JSON，不使用 Razor 當產品 UI），埠 `5080`
- **database：** MySQL 8，庫名 `issue_tracker`

瀏覽器只打後端 HTTP API。後端以 EF Core（Pomelo）存取 MySQL。本輪無登入、無 JWT。

統一回應：

```json
{ "code": 200, "message": "success", "data": {} }
```

成功 HTTP 200 且 `code === 200`。業務錯誤 HTTP 400／404／409，body 仍為上述形狀（`data` 可 null）。前端以 `code === 200` 判斷成功。

# 四、API 規劃

路徑無 `/api` 前綴。JSON 屬性 **camelCase**。

### 4.1 大分類

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 列出大分類 | GET | `/majorCategories` | 無 | `MajorCategory[]` | — |
| 新增 | POST | `/majorCategories` | `{ name }` | 完整大分類列表 | 400 名稱空白／過長；409 重名 |
| 改名 | PUT | `/majorCategories/{id}` | `{ name }` | 完整大分類列表 | 404；400 名稱空白／過長；409 重名 |
| 刪除 | DELETE | `/majorCategories/{id}` | 無 | 完整大分類列表 | 404；409 使用中（message 含筆數）或只剩一個 |
| 列出備選色 | GET | `/colorPresets` | 無 | `string[]`（10 個 hex） | — |

`MajorCategory`：`id`, `name`, `color`, `sortOrder`。`color` 保留欄位但產品畫面不使用。寫入成功 `data` 回傳**更新後完整大分類列表**。刪除時一併刪該大分類下未使用的小分類；有議題掛著則不可刪。

### 4.2 小分類

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 列出小分類 | GET | `/subCategories?majorCategoryId=` | query 可省略＝全部 | `SubCategory[]` | 400 無效大分類 |
| 新增 | POST | `/subCategories` | `{ majorCategoryId, name, color? }` | 該大分類下完整列表 | 400 名稱空白／非備選色；409 同大分類重名 |
| 更新 | PUT | `/subCategories/{id}` | `{ name?, color? }` 至少一個 | 該大分類下完整列表 | 404；400 非備選色；409 重名 |
| 刪除 | DELETE | `/subCategories/{id}` | 無 | 該大分類下完整列表 | 404；409 使用中（message 含筆數） |

`SubCategory`：`id`, `majorCategoryId`, `name`, `color`, `sortOrder`

寫入成功 `data` 回傳**該大分類更新後完整列表**（方便前端直接替換）。

### 4.3 議題

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 列表 | GET | `/issues?majorCategoryId=` | query 可省略 | `IssueListItem[]` | — |
| 單筆 | GET | `/issues/{id}` | 無 | `IssueDetail` | 404 |
| 新增 | POST | `/issues` | `IssueWrite` | `IssueDetail` | 400 驗證；409 編號重複 |
| 更新 | PUT | `/issues/{id}` | `IssueWrite` | `IssueDetail` | 404；400；409 編號重複 |
| 刪除 | DELETE | `/issues/{id}` | 無 | `{ deleted: true }` | 404 |
| 行事曆 | GET | `/issues/calendar?year=&month=` | 年月必填 | `IssueCalendarItem[]` | 400 |
| 排入預計日 | POST | `/issues/{id}/plans` | `{ date }` 單日；`{ date, endDate }` 閉區間；`{ dates }` 多日（優先） | `{ added: true, count }` | 404；400；409 所選皆已排（已有日會略過） |
| 移出預計日 | DELETE | `/issues/{id}/plans?date=` | date 必填 | `{ deleted: true }` | 404 |

`IssueCalendarItem`：`id`, `planId`, `kind`（`due`／`plan`）, `issueNo`, `title`, `content`, `date`, `dueDate`（與 `date` 同值）, `majorCategoryId`, `majorCategoryColor`, `subCategoryColor`

`IssueWrite`：`issueNo`（必填、唯一）, `title`（必填）, `content`, `majorCategoryId`（必填）, `subCategoryId`（可 null）, `dueDate`（可 null，`yyyy-MM-dd`）, `remark`（可 null）

`IssueListItem`／`IssueDetail`：`id`, `issueNo`, `title`, `content`, `majorCategoryId`, `majorCategoryName`, `majorCategoryColor`, `subCategoryId`, `subCategoryName`, `subCategoryColor`, `dueDate`, `remark`, `createdAt`, `updatedAt`

清單／月曆色票取小分類色；無小分類時為 `#8FA8C8`。`majorCategoryColor` 與 `subCategoryColor` 同值，方便舊前端。

驗證：編號非空白且唯一；標題非空白；大分類須存在；若 `subCategoryId` 有值，須存在且屬於該大分類。

## 7.1 邏輯 Entity Model

邏輯 Entity 來自《功能規格書》第七章。

| 實體名稱 | 中文名稱 | 用途 | 主要屬性 | 關聯 | 持久化方式 | 驗證規則 |

## 7.2 實體關聯概覽

- majorCategory 1:N subCategory
- majorCategory 1:N issue
- subCategory 1:N issue（issue.subCategoryId 可空）
- issue 1:N todo
- todo 1:N todo（parentId 自關聯，樹狀）

## 7.3 資料流向

分類設定 → 寫 majorCategory／subCategory → 議題表單讀取下拉。  
議題寫入 → 清單／行事曆讀取。  
TODO 寫入與完成 → 服務層可能更新多筆 todo 的 isCompleted → 回傳整樹。  
刪議題 → 先刪該議題全部 todo 再刪議題。

# 九、例外流程

| 情境 | 行為 |
|------|------|
| 驗證失敗 | 400，message 繁中 |
| 找不到資源 | 404 |
| 大／小分類重名、使用中刪除、只剩一個大分類、TODO 排序集合不符或企圖改掛 | 409 |
| 未處理例外 | 500，message 不暴露堆疊給前端 |

刪小分類：COUNT 指向該 id 的 issue，>0 則 409，message 如「使用中，共 N 筆議題」。  
刪大分類：COUNT 指向該 id 的 issue，>0 則 409；若只剩一個大分類則 409「至少需保留一個大分類」。

# 十、系統限制

- 單人、無登入
- TODO 不可藉 reorder 改 parentId
- 行事曆只含議題 dueDate，不含 TODO、不含預約
- 大分類可經 API 增刪改名，但至少保留一個，且使用中不可刪
- 小分類顏色僅可設為 10 個備選色之一

# 十一、開發注意事項

- 自動完成只在「本次改為完成」且「所有兄弟已完成」時向上；不要每次 GET 重算整棵樹去改庫。
- 顏色存小分類表，前端不要寫死第二份色碼（種子值可與規格色票一致）。
- JSON camelCase；EF 對 DB snake_case。
- 本機 MySQL 連線放設定檔，勿提交真實生產密鑰。
- 單元測試至少覆蓋：自動完成級聯、取消完成不上修、reorder 拒絕改掛。
