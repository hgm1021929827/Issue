# 一、專案介紹

本專案是給個人使用的工作追蹤網頁，用來管理正式議題、分類、以及可多層巢狀的 TODO。來源需求是一份「修正與新增」文件，產品願景包含專案、Excel 匯入、成員、加簽恢復、預約連線等；那些能力列為後續階段，不在本輪實作。

本輪先交付一條可日常使用的核心路徑：設定分類 → 建立與維護正式議題 → 在詳情裡拆解多層 TODO → 從首頁清單與行事曆骨架找到工作。

# 二、專案目標

1. 用四個固定大分類與可維護的小分類，標示議題狀態與顏色。
2. 可新增、編輯、刪除正式議題，並在詳情維護內容、分類、預計完成日、備註與 TODO 樹。
3. TODO 支援多層子項、拖曳同層排序，以及來源檔規定的父項自動完成規則（擴充到每一層）。
4. 首頁以議題清單為主，並以本月行事曆骨架顯示有預計完成日的議題。
5. 單人使用、不登入；成員與客戶只當後續階段的資料，本輪不建帳號。

| 項目 | 需求 |
|------|------|
| 功能目的 | 在各大分類下維護細分狀態；以獨立識別編號保存，不得只存名稱 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 使用者開啟分類設定頁，選擇某個大分類，新增／重新命名／刪除該大分類下的小分類。「預約」大分類預置範例：已發信、預約完成、連線完成、連線取消（可再改名或刪除，刪除仍受使用中檢查）。每個大分類提供「空白」選項，不建立小分類資料。 |
| 功能限制 | 同一大分類下小分類名稱不可重複（大小寫視為相同須擋下）。不同大分類可以使用相同名稱。刪除後即使再建同名，仍是不同小分類（識別編號不同）。本輪刪除前只檢查是否被**正式議題**使用（含議題目前選到的小分類）。後續階段才檢查臨時工作、專案、加簽前原小分類、預約連線。 |
| 注意事項 | 工作資料必須保存小分類識別編號。空白＝空值，不是一筆名叫空白的資料。 |
| 驗收條件 | 同大分類重複名稱無法新增並有提示；跨大分類同名可新增；刪除後重建同名，舊議題仍指向舊識別（若舊筆仍存在）或新筆與舊筆識別不同；使用中的小分類不可刪，並提示使用筆數；空白選項不寫入小分類資料表。 |

| 項目 | 需求 |
|------|------|
| 功能目的 | 建立與維護正式議題，作為 TODO 與後續功能的承載 |

### WT-F04：議題詳情與 TODO 樹

| 項目 | 需求 |
|------|------|
| 功能目的 | 在單一議題下拆解可多層巢狀的 TODO，並支援排序與完成 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 進入議題詳情，看到議題欄位與 TODO 樹。可在任意現有 TODO 下新增子項，也可在根層新增。每筆 TODO 可編輯標題、內容、是否完成，可刪除（含子樹）。同一父項下可拖曳調整排列順序。無子項時以該筆自己的核取標記完成。 |
| 功能限制 | 本輪不可用拖曳把 TODO 改掛到其他父項或改層級；改掛須刪除後重建（或後續階段再做移動）。需要追蹤的 TODO 本輪不提供。層數不設產品上限，畫面以縮排區分；過深時仍須可操作（捲動、縮排上限以可讀為準，不得因此拒絕新增）。 |
| 注意事項 | 子 TODO 欄位與一般 TODO 一致：是否完成、標題、內容、排列順序。多層為討論 Q6＝C 的確認結果。複雜拖曳與深層縮排標為待 Tech Spike 評估。 |
| 驗收條件 | 可建立至少三層巢狀（根－子－孫）並正確顯示縮排；同父項拖曳後重新整理順序且重新整理後順序仍在；拖到其他父項不改變歸屬（或操作被拒絕且資料不變）；刪除父項會刪除其子孫；標題空白不可存。 |

### WT-F05：TODO 完成與父項自動完成

| 項目 | 需求 |
|------|------|
| 功能目的 | 依來源檔規則完成 TODO，並在多層結構下逐層套用自動完成 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 使用者勾選某 TODO 為完成。若該 TODO 的父項底下「所有子項都已完成」，且這次勾選使最後一筆未完成子項變成完成，則系統將該父項標為完成。此規則在每一層套用，並可向上級聯（父項因自動完成而完成，又使其上層全部子項完成時，上層一併自動完成）。使用者仍可手動取消父項完成。取消任一子項完成時，不自動取消祖先。手動勾選或取消任一 TODO，不自動修改其子孫狀態。 |
| 功能限制 | 自動完成只在「勾選最後一筆未完成的子項」時觸發；不是每次檢查整棵樹重算。無子項的 TODO 只靠自己的核取（Q7＝A）。議題完成不由此規則驅動（議題完成只靠大分類，見 WT-F01／F03）。 |
| 注意事項 | 父項自動完成後，子孫保持完成。父項被手動取消完成後，子孫維持原狀。新增子項到已完成的父項底下時，不自動取消該父項完成。 |
| 驗收條件 | 來源檔範例在一層時行為成立（最後一筆子項勾選後父項完成，且可再取消父項）。三層時：孫層最後一筆完成 → 子層自動完成 → 若該子層是父層最後一筆未完成，父層也自動完成。取消任一子孫完成，祖先保持完成。手動完成父項，子孫狀態不變。 |

# 六、功能流程

跨功能主路徑（不重複第四章逐步操作）：

1. 使用者開啟網站 → 首頁（清單＋本月行事曆）。
2. 若尚未設定小分類，可先到分類設定為「處理中」等大分類補細項；也可直接新增議題並選空白小分類。
3. 新增正式議題（預設大分類處理中）→ 出現在清單；若填了預計完成日，同時出現在行事曆對應日。
4. 進入詳情 → 把工作拆成 TODO 樹（可多層）→ 逐項勾選；最後一筆未完成子項勾選時父項自動完成，並可向上級聯。
5. 議題本身要標完成時，把大分類改為「已完成」（不是勾 TODO 核取）。清單與行事曆顏色改為已完成色。
6. 刪除議題則清單、行事曆、該題 TODO 全部消失。

後續階段才會接入：臨時工作、專案匯入、成員與追蹤、加簽恢復、預約上曆。

* **使用者操作：** 輸入、切換大分類（小分類重設為空白或僅保留仍屬新大分類者）、儲存、刪除確認。
* **系統回應：** 成功後回詳情或清單並看到新資料；刪除後回首頁。
* **錯誤狀態：** 標題空白提示必填；儲存失敗顯示訊息。
* **載入狀態：** 編輯時載入原值；儲存中按鈕不可重送。

* **載入狀態：** 樹載入中；空 TODO 顯示「尚無事項」與新增。
* **Spike 狀態：** 已確認可行（遞迴樹＋同父項 dnd-kit）。

* **使用者操作：** 新增、改名、刪除。
* **系統回應：** 列表更新。
* **錯誤狀態：** 同大分類名稱重複提示；使用中不可刪並顯示使用筆數。

* **Spike 狀態：** 已確認可行。

# 九、非功能需求

* **效能：** 個人本機或單人使用；首頁清單與單月行事曆在數百筆議題內應可於數秒內顯示。TODO 單題建議可負擔至少百筆節點。
* **安全性：** 本輪無登入、無對外權限模型；不在畫面或儲存中放入密鑰。部署若暴露到區網，視為使用者自承擔。
* **維護性：** 前後端分離清楚；分類顏色集中一處，避免每頁手寫色碼。
* **擴充性：** 資料須用小分類識別而非名稱；大分類固定有利後續加簽／預約流程掛載。行事曆區塊預留同日多類型項目。
* **語系：** 使用者可見文案繁體中文。
* **資料慣例：** 對齊 `AGENTS.md`：資料庫 snake_case、BIGINT 主鍵；C# 實體 PascalCase。
