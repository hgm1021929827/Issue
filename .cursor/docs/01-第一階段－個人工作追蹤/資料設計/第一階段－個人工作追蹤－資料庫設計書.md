## 一、資料庫設計理念

個人單人系統，結構求清楚、好改。四張表對應四大邏輯實體。不用分片、不用讀寫分離。主鍵一律 `BIGINT AUTO_INCREMENT`。表名與欄位 `snake_case`。C# 實體 PascalCase 對應 underscore。

## 二、Table 清單

| 表名 | 中文 | 用途 |
|------|------|------|
| major_category | 大分類 | 使用者維護；空庫種子預約、議題分類 |
| sub_category | 小分類 | 各大分類下的細分 |
| issue | 正式議題 | 工作主體 |
| issue_plan | 預計項目 | 議題排入某一天 |
| issue_todo | TODO | 議題下多層事項 |

資料庫名稱建議：`issue_tracker`，charset `utf8mb4`。

## 三、Table 詳細設計

### major_category

中文名稱：大分類

用途：儲存大分類名稱。空庫時種子「預約、議題分類」，之後由使用者增刪改名。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| major_category_id | 編號 | BIGINT | PRIMARY KEY | 否 | AUTO_INCREMENT | 主鍵 |
| category_name | 名稱 | VARCHAR(50) | NOT NULL；UNIQUE | 否 | — | 全系統不可重名 |
| color_hex | 顏色 | VARCHAR(7) | NOT NULL | 否 | — | 如 `#4A7C6F` |
| sort_order | 排列順序 | INT | NOT NULL | 否 | — | 畫面順序 |

種子（id 可隨 AUTO_INCREMENT；**僅在表為空時**寫入「預約／議題分類」，之後不刪除自訂列）：

| id | 名稱 | 顏色 | sort |
|----|------|------|------|
| — | 預約 | `#8FA8C8` | 1 |
| — | 議題分類 | `#8FA8C8` | 2 |

應用程式可新增、改名、刪除。刪除條件：至少保留一筆；沒有議題掛著。刪除時一併刪該大分類下的小分類。

### sub_category

中文名稱：小分類

用途：使用者維護的細分狀態。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| sub_category_id | 編號 | BIGINT | PRIMARY KEY | 否 | AUTO_INCREMENT | 主鍵 |
| major_category_id | 所屬大分類 | BIGINT | NOT NULL；FK | 否 | — | 指向 major_category |
| sub_category_name | 名稱 | VARCHAR(50) | NOT NULL | 否 | — | 同大分類下不可重複 |
| color_hex | 顏色 | VARCHAR(7) | NOT NULL | 否 | `#8FA8C8` | 10 個備選色之一 |
| sort_order | 排列順序 | INT | NOT NULL | 否 | — | 同大分類下排序 |

種子：名稱為「預約／議題分類」的大分類預置「已發信、預約完成、連線完成、連線取消」及對應色票。自訂大分類不預置小分類。

### issue

中文名稱：正式議題

用途：儲存個人工作主體。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| issue_id | 編號 | BIGINT | PRIMARY KEY | 否 | AUTO_INCREMENT | 內部主鍵 |
| issue_no | 議題編號 | VARCHAR(50) | NOT NULL；UNIQUE | 否 | — | 使用者輸入，畫面顯示 |
| title | 標題 | VARCHAR(200) | NOT NULL | 否 | — | 顯示標題 |
| content | 內容 | VARCHAR(4000) | NOT NULL | 否 | `''` | 可空字串 |
| major_category_id | 大分類 | BIGINT | NOT NULL；FK | 否 | — | 狀態 |
| sub_category_id | 小分類 | BIGINT | FK | 是 | NULL | 空白小分類 |
| due_date | 預計完成日 | DATE | — | 是 | NULL | 行事曆用 |
| remark | 備註 | VARCHAR(2000) | — | 是 | NULL | 選填 |
| created_at | 建立時間 | DATETIME | NOT NULL | 否 | CURRENT_TIMESTAMP | — |
| updated_at | 更新時間 | DATETIME | NOT NULL | 否 | CURRENT_TIMESTAMP | 更新時刷新 |

### issue_plan

中文名稱：預計項目

用途：把議題排入某一天，可與到期日不同、可多天。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| plan_id | 編號 | BIGINT | PRIMARY KEY | 否 | AUTO_INCREMENT | 主鍵 |
| issue_id | 議題 | BIGINT | NOT NULL；FK | 否 | — | 指向 issue |
| plan_date | 預計日 | DATE | NOT NULL | 否 | — | 行事曆格子 |

### issue_todo

中文名稱：TODO

用途：議題下可多層巢狀的待辦。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| todo_id | 編號 | BIGINT | PRIMARY KEY | 否 | AUTO_INCREMENT | 主鍵 |
| issue_id | 所屬議題 | BIGINT | NOT NULL；FK | 否 | — | 所屬議題 |
| parent_todo_id | 父 TODO | BIGINT | FK | 是 | NULL | 根層 NULL |
| is_completed | 是否完成 | TINYINT(1) | NOT NULL | 否 | 0 | 0／1 |
| title | 標題 | VARCHAR(200) | NOT NULL | 否 | — | — |
| content | 內容 | VARCHAR(2000) | NOT NULL | 否 | `''` | 可空字串 |
| sort_order | 排列順序 | INT | NOT NULL | 否 | — | 同父項下順序 |
| created_at | 建立時間 | DATETIME | NOT NULL | 否 | CURRENT_TIMESTAMP | — |
| updated_at | 更新時間 | DATETIME | NOT NULL | 否 | CURRENT_TIMESTAMP | — |

## 四、Table 關聯

- `sub_category.major_category_id` → `major_category.major_category_id`（ON DELETE RESTRICT）
- `issue.major_category_id` → `major_category.major_category_id`（ON DELETE RESTRICT）
- `issue.sub_category_id` → `sub_category.sub_category_id`（ON DELETE RESTRICT）
- `issue_plan.issue_id` → `issue.issue_id`（ON DELETE CASCADE）
- `issue_todo.issue_id` → `issue.issue_id`（ON DELETE CASCADE）
- `issue_todo.parent_todo_id` → `issue_todo.todo_id`（ON DELETE CASCADE）

刪議題時子 TODO 隨 CASCADE 刪除。刪父 TODO 時子孫 CASCADE 刪除。

## 五、Index 建議

- UNIQUE (`category_name`) on `major_category`
- UNIQUE (`major_category_id`, `sub_category_name`) on `sub_category`
- UNIQUE (`issue_no`) on `issue`
- INDEX (`major_category_id`) on `issue`
- INDEX (`due_date`) on `issue`
- UNIQUE (`issue_id`, `plan_date`) on `issue_plan`
- INDEX (`issue_id`, `parent_todo_id`, `sort_order`) on `issue_todo`

## 六、Constraint

- 大分類名稱全系統唯一（上列 UNIQUE；應用層再以忽略大小寫檢查）。
- 小分類名稱在同一大分類下唯一（上列 UNIQUE）。
- 應用層再檢查：issue.sub_category 的 major 必須等於 issue.major_category。
- 應用層：parent_todo 與自身必須同一 issue_id；reorder 不可改 parent。

## 七、資料生命週期

- 大分類：空庫種子兩筆；使用者可增刪改名。使用中或只剩一筆不可刪。刪除時一併刪其小分類。
- 小分類：使用者刪；使用中（issue 指向）不可刪。
- 議題：使用者刪即永久刪除（含 TODO）。
- TODO：隨父或議題刪除。

## 八、命名規範

表與欄位 snake_case。C#：`MajorCategoryId` 對 `major_category_id`。布林 `is_completed` → `IsCompleted`。

## 九、設計決策

- 表名用 `issue_todo` 而非 `todo`，避免保留字與語意不清。
- `content` 用 NOT NULL 預設空字串，避免前後端 null／空混用。
- 完成狀態不做成資料庫觸發器，由服務層級聯，以便測試與符合「只在勾選最後一筆時觸發」。
