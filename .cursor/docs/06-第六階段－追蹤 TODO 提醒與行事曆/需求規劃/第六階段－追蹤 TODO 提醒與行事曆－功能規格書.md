# 一、專案介紹

第五階段已有需要追蹤的 TODO。本階段為每筆追蹤增加**選填的提醒日期**（只到日、最多一天），有填且尚未完成時，自動出現在首頁既有行事曆該天。不是第二套「預計項目」拖曳，也不是外部日曆或推播。

# 二、專案目標

1. 議題／專案／專案議題上的追蹤 TODO 皆可填或清空提醒日。
2. 未完成且有提醒日的列出現在月曆該日；勾完成後不再出現。
3. 月曆第三個視角「追蹤提醒」（預設開）；點擊與首頁跳轉相同並定位該筆。
4. 首頁「需要追蹤項目」加「提醒日」欄。

# 三、產品定位

| 欄位 | 說明 |
|------|------|
| **需求類型** | ① Web 應用功能（含 UI／API，需 Database） |
| **本期範圍** | 提醒日期欄；行事曆同步與第三視角；點擊定位；首頁列表顯示日期 |
| **不在範圍** | 工作項次／Excel；加簽；預約；登入；ICS／Google；郵件推播；多天提醒；時刻；月曆拖曳設定或點掉提醒；一般 TODO 日期。本輪**有** Database、API、程式實作。 |

# 四、功能需求

### TR-F01：追蹤 TODO 提醒日期

| 項目 | 需求 |
|------|------|
| 功能目的 | 記下「哪一天要跟人」 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 新增／編輯追蹤 TODO 時可選提醒日（既有日期元件）。可留空。儲存後詳情列上可看見日期。一筆最多一個日期；改日期即改月曆位置；清空則不再上月曆。 |
| 功能限制 | 只到日、不含時刻。不可一次填多天。不因此改變標題、對象、完成規則。舊資料無日期視為空。 |
| 注意事項 | 文案用「提醒日」。三種工作同一欄。 |
| 驗收條件 | 三種工作都能存提醒日與清空；空白可存；重整後日期仍在。 |

### TR-F02：同步到行事曆

| 項目 | 需求 |
|------|------|
| 功能目的 | 有提醒日的未完成追蹤出現在首頁月曆 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 儲存有提醒日的未完成追蹤後，切到該月可見標記。標記須能與到期日、預計項目區分（圖示或樣式）。點擊見 TR-F04。不可從月曆拖曳來設定日期，也不可在月曆上刪除該筆追蹤。 |
| 功能限制 | 已完成不上月曆。無提醒日不上月曆。不進「預計項目」資料。 |
| 注意事項 | 逾期未完成仍顯示在該日格子。換月依該月查詢。 |
| 驗收條件 | 有日期未完成出現在正確日；完成後標記消失；清空日期後標記消失；預計項目拖曳與提醒互不改寫。 |

### TR-F03：行事曆視角「追蹤提醒」

| 項目 | 需求 |
|------|------|
| 功能目的 | 可獨立開關追蹤標記 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 視角列在「到期日」「預計項目」旁加「追蹤提醒」，預設開啟。三種可任意組合。只關到期日時，追蹤標記仍可顯示（若追蹤開關開著）。三種全關時提示至少選一種。 |
| 功能限制 | 不把追蹤併進到期日開關。 |
| 注意事項 | 開關文案固定「追蹤提醒」。互動待 Spike（現有非 plan 皆當 due）。 |
| 驗收條件 | 預設看得到追蹤標記；關掉「追蹤提醒」後標記消失、到期與預計項目不受影響；關掉「到期日」時追蹤仍在（若該開關係開）。 |

### TR-F04：月曆點擊跳轉

| 項目 | 需求 |
|------|------|
| 功能目的 | 從月曆進到該筆追蹤 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 點標記：路徑與第五階段首頁跳轉相同（議題／專案／專案議題＋`trackTodo`，專案議題含 `item`）。定位與找不到橫幅沿用第五階段。 |
| 功能限制 | 不新開獨立頁。 |
| 注意事項 | 標記 `id` 必須是追蹤 TODO 識別，不可只連到工作而丟了是哪一筆。 |
| 驗收條件 | 三種工作從月曆點進後能辨識該列；已刪則詳情仍開並提示找不到。 |

### TR-F05：首頁列表顯示提醒日

| 項目 | 需求 |
|------|------|
| 功能目的 | 不必開月曆也能看到哪天要跟 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 「需要追蹤項目」加欄「提醒日」。有值顯示日期；無則「—」。其餘欄不變。仍只列未完成、不可在此勾完成。 |
| 功能限制 | 不在首頁改日期。 |
| 注意事項 | 欄序建議：工作類型、所屬工作、標題、追蹤對象、提醒日、跳轉。 |
| 驗收條件 | 有日期的列看得到日期；無日期顯示「—」。 |

# 五、角色權限

僅使用者本人（單人、無登入）。與第五階段相同。

# 六、功能流程

1. 在追蹤表單填提醒日（可空）並儲存。
2. 未完成且有日期 → 首頁列表有提醒日、月曆該日有標記（視角開著時）。
3. 點月曆或列表跳轉 → 詳情定位該筆。
4. 勾完成或清空日期 → 月曆與「還要跟」的語意一致：列表在完成後本來就不列；月曆也不再列。

# 七、資料需求

增量掛在既有「追蹤 TODO」上，不新增業務實體。持久化 Database。

| 資料名稱 | 用途 | 是否持久化 | 持久化方式 | 關聯 |
|----------|------|------------|------------|------|
| 追蹤 TODO（增量） | 記住提醒日並供月曆查詢 | 是 | Database | 仍恰好屬於一種工作 |

### 追蹤 TODO（本輪新增屬性）

| 屬性名稱 | 中文名稱 | 邏輯型態 | 驗證限制 | 是否允許空值 |
|----------|----------|----------|----------|--------------|
| reminderDate | 提醒日 | 日期（只到日） | 可空；有值須為有效日；一筆最多一個 | 是 |

既有屬性（完成、標題、內容、對象、排序等）本輪不改規則。

# 八、UI／UX 需求

### 8.1 追蹤表單與列

* **畫面元素：** 「提醒日」日期欄；列上可看到日期或空白。
* **使用者操作：** 選日或清空後儲存。
* **系統回應：** 列表與月曆更新。
* **錯誤狀態：** 頁內橫幅。
* **載入狀態：** 與既有追蹤表單相同。
* **Spike 狀態：** 已確認可行（既有日期元件）。

### 8.2 行事曆標記與視角

* **畫面元素：** 「追蹤提醒」開關；格子內追蹤標記（圖示／樣式異於 due、plan）。
* **使用者操作：** 切換視角；點標記跳轉。不可點 X 刪提醒。
* **系統回應：** 依開關過濾；跳轉詳情。
* **錯誤狀態：** 三種視角全關時提示至少選一種。
* **載入狀態：** 切月重載既有 calendar API。
* **Spike 狀態：** 待評估（`kind` 目前二分）。

### 8.3 首頁追蹤表

* **畫面元素：** 欄「提醒日」。
* **使用者操作：** 仍只點跳轉。
* **系統回應：** 顯示日期或「—」。
* **錯誤狀態：** 同第五階段。
* **載入狀態：** 同第五階段。
* **Spike 狀態：** 已確認可行。

# 九、非功能需求

* **效能：** 月曆仍一次載入該月；追蹤標記以該月未完成有日期者為準。
* **安全性：** 無登入。
* **維護性：** 提醒是追蹤 TODO 的欄，不是另一張排程表。
* **語系：** 繁體中文。
