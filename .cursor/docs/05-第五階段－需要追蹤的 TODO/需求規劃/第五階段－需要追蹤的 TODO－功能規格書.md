# 一、專案介紹

本階段新增**需要追蹤的 TODO**：在正式議題、專案、專案議題詳情各有獨立清單，用來記錄「要追誰回覆」。與第一階段一般 TODO 分開顯示、互不從屬。

每筆含是否完成、標題、可空內容、追蹤對象類型與實際對象。對象用兩層下拉：內部成員（公司成員）或客戶窗口（僅該工作所屬客戶公司）。首頁新增「需要追蹤項目」，只列未完成並可跳轉詳情。

成員與客戶仍不是帳號。不做加簽、預約、工作項次、Excel、登入。

# 二、專案目標

1. 正式議題、專案、專案議題詳情皆可增查改刪追蹤 TODO；與一般 TODO 分區顯示。
2. 單層平鋪、可同清單拖曳排序；無子項、無父項自動完成。
3. 追蹤對象類型與對象必填；內部顯示「中文名（英文名）」；客戶窗口只列該工作廠商底下的窗口。
4. 無廠商、該公司無窗口時有明確提示，不可改選別家窗口。有客戶窗口類追蹤時不可改該工作（或專案）廠商。
5. 刪成員、客戶公司、窗口前檢查追蹤占用並顯示筆數。刪工作則連刪其追蹤 TODO。
6. 首頁「需要追蹤項目」只列未完成；跳轉進入對應詳情並盡力定位該筆。

# 四、功能需求

### TT-F01：詳情頁追蹤 TODO 清單與 CRUD

| 項目 | 需求 |
|------|------|
| 功能目的 | 在所屬工作上記「要追誰」，與一般 TODO 分開 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 正式議題詳情、專案詳情、專案議題編輯區（或專案議題詳情，與現有編輯入口同一層）各有「需要追蹤的 TODO」區塊，不混進一般 TODO 樹。可新增：標題（必填）、內容（可空）、對象類型與對象（必填，見 TT-F02）、是否完成（預設否）。可改同一組欄位、勾選或取消完成、刪除（dialog 確認，單筆無子項）。列表依排列順序顯示。新增工作尚未存檔時，不可先建追蹤 TODO（須先有所屬工作識別）。 |

| 注意事項 | 用詞固定「需要追蹤的 TODO」。正式議題詳情：本區塊與一般 TODO 樹並陳、分區標題分開。專案／專案議題目前沒有一般 TODO，本輪只出現追蹤區塊，不順便做一般 TODO。 |
| 驗收條件 | 三種工作都能新增至少一筆並看見標題與對象；標題空白不可存；完成核取可來回；刪確認後該筆消失且不影響一般 TODO；正式議題的一般 TODO 樹不含追蹤列。 |

### TT-F03：無廠商與無窗口提示

| 項目 | 需求 |
|------|------|
| 功能目的 | 缺資料時告訴使用者下一步，不讓選錯公司 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |

| 功能限制 | 不因此把廠商改成可空；新存專案／正式議題仍依第四階段必填。本規則服務舊資料尚未補廠商、以及有公司無窗口。 |
| 注意事項 | 專案議題無自己的廠商欄；提示導向去專案補廠商。 |
| 驗收條件 | 無廠商時選客戶窗口有提示且存檔失敗；該公司零窗口時有提示且存檔失敗；有窗口時只出現該公司窗口。 |

| 項目 | 需求 |

| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 在該工作的追蹤清單內拖曳調整順序。只允許同清單內排序；放開後順序持久化。重新整理後順序仍在。 |

### TT-F05：首頁需要追蹤項目

| 項目 | 需求 |
|------|------|
| 功能目的 | 一處看見尚未完成的追蹤並進入工作 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 首頁既有議題清單與行事曆之外，新增「需要追蹤項目」區塊。每列：所屬工作類型（議題／專案／專案議題）、所屬工作、標題、追蹤對象、跳轉。只列未完成。所屬工作：議題＝編號（有則顯示）與標題；專案＝代號與名稱；專案議題＝項次與標題（可附專案代號以分辨）。追蹤對象：內部＝「中文名（英文名）」；窗口＝窗口名稱（可附公司名若有助分辨）。點跳轉見 TT-F06。本輪首頁**不可**直接勾完成。 |
| 功能限制 | 不含已完成。不做「含已完成」切換。不進行事曆（追蹤 TODO 無獨立日期）。 |
| 注意事項 | 無未完成列時顯示空狀態（不是錯誤）。排序：依所屬工作內排列順序，跨工作時較新的工作或較新的列在前（穩定、可預測即可，細節交 SA，但同一工作內須與詳情順序一致）。 |
| 驗收條件 | 未完成出現在首頁；勾完成後離開首頁、取消完成後回來；已完成不出現；三種工作類型列文案正確；空狀態可見。 |

### TT-F06：跳轉與定位

| 項目 | 需求 |
|------|------|
| 功能目的 | 從首頁進到該筆追蹤 TODO |
| 優先級 | Must |
| 是否本輪 MVP | 是 |

| 功能限制 | 不新開獨立「追蹤詳情頁」。定位互動待 Tech Spike；若無法可靠捲動，降級為打開正確詳情且追蹤區塊在視窗內可見。 |
| 注意事項 | 不得跳錯工作類型。 |

### TT-F07：有客戶窗口追蹤時不可改廠商

| 項目 | 需求 |
|------|------|
| 功能目的 | 避免窗口與所屬公司不一致 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 儲存正式議題且廠商與原值不同：若該議題有任一「客戶窗口」類追蹤 TODO，禁止儲存，橫幅含這類追蹤筆數，須先改對象為內部成員、換成新公司窗口、或刪那些 TODO。儲存專案且廠商與原值不同：該專案自己的客戶窗口追蹤，以及其底下所有專案議題的客戶窗口追蹤，任一存在即擋，提示分別列出大於 0 的段（專案／專案議題）。內部成員類追蹤不擋改廠商。新增（尚無識別）無此檢查。 |
| 功能限制 | 不自動清空或改寫追蹤對象。專案議題本身不能改廠商（跟隨專案），故無專案議題表單上的改廠商檢查。 |
| 注意事項 | 文案繁中，例如「無法更改廠商，尚有 2 筆需要追蹤的 TODO 使用客戶窗口」。 |
| 驗收條件 | 議題有客戶窗口追蹤時改廠商存檔失敗且資料不變；只剩內部成員追蹤時可改廠商；專案改廠商會算到專案議題上的客戶窗口追蹤。 |

### TT-F08：刪通訊錄占用檢查（增量）

| 項目 | 需求 |
|------|------|
| 功能目的 | 使用中的成員與窗口不可默默消失 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 在第四階段 MF-F08 之上增加：刪公司成員：若被任一追蹤 TODO 當內部對象，禁止並顯示追蹤 TODO 筆數（與專案負責人員筆數並列，只列大於 0 的段）。刪客戶窗口：若被任一追蹤 TODO 當窗口對象，禁止並顯示筆數。刪客戶公司：除既有專案／正式議題廠商占用外，若其底下窗口被追蹤占用，一併提示追蹤筆數，不刪。不自動清空引用。刪單筆聯絡仍不檢查追蹤。預約仍不檢查。 |
| 功能限制 | 不因本輪而允許刪掉仍被專案當廠商的公司。 |
| 注意事項 | 文案繁中，例如「使用中，共 1 筆專案、2 筆需要追蹤的 TODO」。 |
| 驗收條件 | 被當內部追蹤對象的成員刪不掉；被當窗口追蹤對象的窗口刪不掉；其公司也刪不掉；沒被追蹤且無其他占用者刪得掉。 |

### TT-F09：刪工作連刪追蹤 TODO

| 項目 | 需求 |
|------|------|
| 功能目的 | 工作不在時追蹤不殘留 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 刪正式議題：連同一般 TODO 與該議題追蹤 TODO。刪專案議題：連同該筆追蹤 TODO。刪專案：既有連刪專案議題，一併刪專案自己的追蹤 TODO 與被連刪之專案議題上的追蹤 TODO。刪前確認 dialog 可提示將一併刪除追蹤筆數（大於 0 才顯示該段）。 |
| 功能限制 | 無回收筒。 |
| 注意事項 | 對齊刪議題連刪一般 TODO。 |
| 驗收條件 | 刪議題後其追蹤不再出現於首頁；刪專案後專案與專案議題的追蹤皆消失。 |

# 五、角色權限

本輪只有**使用者本人**（單人、無登入）。公司成員與客戶窗口不是操作者，只是追蹤對象資料。

| 角色 | 可操作 |
|------|------|
| 使用者 | 本輪全部畫面：三種工作上的追蹤 CRUD、首頁列表與跳轉 |
| 內部成員／客戶窗口 | 不是操作者 |

無訪客、無管理員分流。

# 六、功能流程

跨功能主路徑（不重複第四章逐步操作）：

1. 使用者確認工作已有廠商（舊資料先補），必要時在成員頁建窗口或成員。
2. 進正式議題／專案／專案議題詳情 → 在追蹤區塊新增列 → 選類型與對象 → 存檔。
3. 未完成列出現在首頁「需要追蹤項目」→ 跳轉回詳情（定位該筆）。
4. 對方處理完後在詳情勾完成 → 首頁該列消失；取消完成則再出現。
5. 同工作多筆可拖曳排序；詳情與首頁同一工作內順序一致。
6. 要改廠商前，先處理客戶窗口類追蹤；要刪成員／窗口前，先改追蹤或刪那些 TODO。
7. 刪工作則追蹤一併消失。

後續階段才接入：加簽、預約、工作項次／Excel、臨時工作、登入。

# 七、資料需求

本輪有 Database 持久化。不設計表名與 SQL。

### 7.1 資料清單

| 資料名稱 | 用途 | 是否持久化 | 持久化方式 | 關聯 |
|----------|------|------------|------------|------|
| 追蹤 TODO | 某工作上要追蹤的事項與對象 | 是 | Database | 必屬恰好一種工作：正式議題或專案或專案議題；指向一位公司成員或一個客戶窗口 |
| 正式議題（既有） | 可掛多筆追蹤 TODO | 是 | Database | 一對多追蹤 TODO；廠商語意不變 |
| 專案（既有） | 可掛多筆追蹤 TODO | 是 | Database | 一對多追蹤 TODO |
| 專案議題（既有） | 可掛多筆追蹤 TODO | 是 | Database | 一對多追蹤 TODO；窗口清單跟隨專案廠商 |

### 7.2 追蹤 TODO 屬性明細

| 屬性名稱 | 中文名稱 | 邏輯型態 | 驗證限制 | 是否允許空值 |
|----------|----------|----------|----------|--------------|
| 識別 | 識別 | 長整數 | 系統給定、唯一 | 否 |
| 所屬工作類型 | 所屬工作類型 | 列舉 | 必填；議題／專案／專案議題 恰好一種 | 否 |
| 所屬工作 | 所屬工作 | 長整數（邏輯參照） | 必填；須為該類型現有工作 | 否 |

# 八、UI／UX 需求

視覺對齊第二階段。各區塊 Spike 狀態如下；Tech Spike 完成後須回寫。

### 8.1 詳情－需要追蹤的 TODO 區塊

* **畫面元素：** 分區標題「需要追蹤的 TODO」；列表列（完成核取、標題、對象摘要、內容可展開或次行）；新增；編輯欄位（標題、內容、兩層下拉）；刪除；拖曳把手。正式議題頁與一般 TODO 樹分開，不得做成同一棵樹的節點。
* **使用者操作：** 新增、編輯、勾完成、刪除確認、同清單拖曳。
* **系統回應：** 列表更新；完成狀態影響首頁。
* **錯誤狀態：** 驗證失敗、無廠商／無窗口／無成員、對象與類型不一致。
* **載入狀態：** 區塊載入中；無資料時空狀態與新增入口。
* **Spike 狀態：** 待評估（與一般 TODO 並陳是否擁擠；單層拖曳）。

### 8.2 兩層下拉

* **畫面元素：** 對象類型下拉；實際對象下拉；缺資料說明文字。
* **使用者操作：** 先選類型再選人；改類型清空第二層。
* **系統回應：** 第二層選項依類型與廠商重載。
* **錯誤狀態：** 見 TT-F02／F03。
* **載入狀態：** 第二層載入中。
* **Spike 狀態：** 已確認可行（常規連動下拉）。

### 8.3 首頁－需要追蹤項目

* **畫面元素：** 區塊標題「需要追蹤項目」；表列欄：工作類型、所屬工作、標題、追蹤對象、跳轉按鈕。置於首頁，不取代議題清單與行事曆。
* **使用者操作：** 點跳轉。不可在此勾完成。
* **系統回應：** 進入對應詳情。
* **錯誤狀態：** 載入失敗可重試。
* **載入狀態：** 載入中；無未完成時空狀態（例如「目前沒有需要追蹤的項目」）。
* **Spike 狀態：** 待評估（與清單／行事曆同屏版面）。

### 8.4 跳轉定位

* **畫面元素：** 目標列高亮或捲入視窗；找不到時橫幅。
* **使用者操作：** 從首頁點跳轉。
* **系統回應：** 正確工作詳情；盡力標示該筆。
* **錯誤狀態：** 該筆已刪：詳情仍開、橫幅說明。
* **載入狀態：** 詳情載入後再定位。
* **Spike 狀態：** 待評估（捲動／高亮；不可行則降級為追蹤區塊可見）。

### 8.5 占用與改廠商錯誤

* **畫面元素：** 頁內橫幅；刪除失敗不關確認 dialog 或關閉後顯示橫幅（與第四階段一致即可）。
* **使用者操作：** 存檔改廠商、刪成員／公司／窗口。
* **系統回應：** 失敗且資料不變；message 含筆數。
* **錯誤狀態：** 使用中不可改／不可刪。
* **載入狀態：** 送出中不可重複點。
* **Spike 狀態：** 已確認可行。

# 九、非功能需求

* **效能：** 首頁未完成追蹤以數百筆為準，一次載入可於數秒內顯示。單工作下數十筆拖曳仍可操作。
* **安全性：** 無登入；不把追蹤對象當帳號。
* **維護性：** 對象類型集中一處列舉；三種工作共用同一套追蹤規則。
* **擴充性：** 之後預約窗口過濾可重用「依所屬公司列窗口」；追蹤 TODO 不列入連線處理事項（來源 10.4）。
* **語系：** 繁體中文。
