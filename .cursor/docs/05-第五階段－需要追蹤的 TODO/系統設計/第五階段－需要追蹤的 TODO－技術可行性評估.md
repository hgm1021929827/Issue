# 第五階段－需要追蹤的 TODO－技術可行性評估

**角色：** RD（Tech Spike，非正式開發）  
**日期：** 2026-09-04  
**依據：** 規格書 §8.1／8.3／8.4 待評估項、系統設計草擬 API／UI

## 結論

**可行。** 沿用既有 React SPA、ASP.NET Core 9、MySQL、粉彩 token、`AppSelect`／`AppDialog`，以及一般 TODO 的同層拖曳與專案頁 `?item=` 高亮。不必新元件庫。

本輪無須於 Spike 交付正式功能程式。

## 評估項目

| 項目 | 結果 | 說明 |
|------|------|------|
| 詳情兩區塊並陳 | 可行 | 議題頁一般 TODO 樹下方（或上方獨立 card）再放追蹤清單。專案頁主資料下加區塊；專案議題在既有編輯 dialog／表單內加同一元件。不加第三套視覺。 |
| 單層拖曳排序 | 可行 | 對齊 `TodoTree` 同層 reorder：HTML5 drag 或既有把手；`PUT .../reorder` 送該工作全部 id 順序。不改掛、無樹。 |
| 兩層下拉 | 可行 | 兩個 `AppSelect`；成員打既有 `/company-members`；窗口打該公司聯絡列表（見系統設計輕量 GET）。 |
| 首頁追蹤區塊 | 可行 | 首頁現有清單＋行事曆再加一張 card；欄位用既有 table／list class。不塞進行事曆。 |
| 跳轉定位 | 可行 | 對齊專案頁已有 `?item=`：`/issues/{id}?trackTodo=`、`/projects/{id}?trackTodo=`、`/projects/{id}?item=&trackTodo=`。`scrollIntoView`＋短暫高亮 class。專案議題先打開該列編輯區再標追蹤列。找不到列則開詳情＋橫幅。 |
| 改廠商／刪除 COUNT | 可行 | 與 MF-F08 同一 409 模式。 |
| 多型所屬工作 | 可行 | 一張追蹤表、三組可空工作參照由 DA 定；API 分三條 nested 路徑，應用層保證恰好一個有值。 |
