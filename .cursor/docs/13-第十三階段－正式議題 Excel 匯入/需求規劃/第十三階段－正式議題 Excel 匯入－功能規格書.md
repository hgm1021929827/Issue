# 一、專案介紹

本階段讓使用者把 UOF 匯出的**議題清單**（`議題匯入範本.xls`，實為 HTML 表格）寫進網頁的**正式議題**。只匯與目前使用者相關的列；以表單編號對上既有議題編號。曾匯入過的議題，編號／標題／內容／預計完成日／廠商改為唯讀，只能再匯入更新。再次匯入時，以前匯進來、這次檔裡卻沒出現的單，不可自動刪，由使用者在結果頁選保留或刪除。

不做加簽保存／恢復、預約、臨時工作、登入、正式議題工時。匯入可寫入小分類「加簽」。順手修正第十二階段 Q-12-01（專案匯入決策空陣列仍成功）。

# 二、專案目標

1. `/issues` 可「匯入議題」：一次一檔；下拉目前使用者（記住上次）；大分類固定「議題」；下拉「處理中」「加簽」「已結案」三個小分類（記住上次）。
2. 讀 UOF HTML 表格。SA、工程師-1、工程師-2 任一欄包含目前使用者中文名或英文名才匯入。
3. 表單編號＝議題編號。寫入標題、內容、預計完成日、廠商；大分類一律「議題」。小分類見 II-F07（狀態含結案一律已結案；處理中才走工程師／簽核者判斷與結果頁加簽）。不覆蓋備註，不碰 TODO／追蹤／預計項目。
4. 廠商從「客戶名稱 : …」對主檔；對不上則自動新增只有名稱的客戶公司。
5. 結果頁：新增／更新／異常；未找到只含曾經匯入過、本次篩選結果沒出現的議題，選保留（明顯標示）或刪除。
6. 曾匯入的議題，上述管理欄唯讀。手建議題維持可改。
7. 專案 `import-decisions` 在決策未覆蓋本次未找到時不得回成功。

# 四、功能需求

### II-F01：議題列表匯入入口

| 項目 | 需求 |
|------|------|
| 功能目的 | 從正式議題清單啟動匯入 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | `/issues` 標題列「新增議題」旁加「匯入議題」。開啟對話：選一個檔、目前使用者、處理中／加簽／已結案三個小分類。確定後走 II-F02～F10。議題詳情、首頁不放匯入。 |
| 功能限制 | 不可一次選多檔。不執行檔內腳本。不是專案 Excel 匯入，兩條入口分開。 |
| 注意事項 | 無公司成員時提示先到成員頁新增，不可匯入。三個小分類都必選。 |
| 驗收條件 | 只有 `/issues` 看得到「匯入議題」；詳情頁沒有此鈕；無成員時無法送出。 |

### II-F02：目前使用者與分類下拉

| 項目 | 需求 |
|------|------|
| 功能目的 | 指定「這次我是誰」以及處理中／加簽／已結案對應哪三個小分類 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 目前使用者＝公司成員下拉（顯示「中文名（英文名）」），必選。預設上次成功匯入選過的成員（本機記住即可）；沒紀錄則請使用者選。大分類固定「議題」（若無則「議題分類」）。處理中／加簽／已結案三個小分類下拉（僅該大分類底下），必選且不可選同一個。預設：上次選過的三個 id；沒紀錄則名稱等於「處理中」「加簽」「已結案」者；找不到則空白請使用者選。 |
| 功能限制 | 不是登入身分。不可略過三個小分類。 |
| 注意事項 | 啟動時 seed 確保大分類「議題」與小分類「處理中」「加簽」「已結案」。匯入不新建分類。 |
| 驗收條件 | 第二次開對話預設仍是上次那位成員與上次三個小分類；任兩小分類選成同一個不可送出。 |

### II-F03：讀取 UOF HTML 檔

| 項目 | 需求 |
|------|------|
| 功能目的 | 把 `議題匯入範本.xls` 當成表格讀進來 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 接受副檔名 `.xls` 或 `.html`。檔內須能找到表頭列，欄名對照（去空白）：申請者、申請時間、結案時間、表單編號、狀態、目前簽核者、簽核者職級、預計完成日、SA、工程師-1、工程師-2、展延時間(1)、展延時間(2)、議題標題、議題內容、廠商資訊。表頭可用 HTML 實體編碼，解析後須當成上述中文名。第一張符合的表格即可。開檔失敗、找不到表頭或缺「表單編號」「議題標題」→ 整批不寫入，頁內提示格式。 |
| 功能限制 | 不支援真正的 `.xlsx` 專案檔當本輪來源。不讀專案「工作項目／議題單」。 |
| 注意事項 | 儲存格可能含 `<br>` 與 `&nbsp;`，讀成純文字時換行保留、連續空白可正規化。解析細節交 Spike。 |
| 驗收條件 | 用 Template 範本可讀出表單編號與標題；把副檔名改成亂檔則不寫入且提示。 |

### II-F04：依 SA／工程師篩選

| 項目 | 需求 |
|------|------|
| 功能目的 | 只匯與目前使用者相關的列 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 列通過條件：SA、工程師-1、工程師-2 **任一**儲存格（去空白）包含目前使用者中文名或英文名（忽略大小寫）。三欄皆空或不含該人 → 本列不匯入，也不算「未找到」來源（從未進入本次結果）。不比對申請者、目前簽核者。 |
| 功能限制 | 不做 `All` 萬用字（範本沒有）。短英文名可能誤中，與第十二階段同一取捨。 |
| 注意事項 | 樣本值如 `李哲瑋(yahome\J073)`：比中文名即可，不必解析網域帳號。 |
| 驗收條件 | 目前使用者中文名只出現在 SA 的列會匯入；三欄都沒有該人的列不出現在新增／更新。 |

### II-F05：以表單編號新增或更新

| 項目 | 需求 |
|------|------|
| 功能目的 | 用 UOF 表單編號對上正式議題編號 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 有效列須表單編號、議題標題皆非空。編號與既有 `issueNo` 相同（忽略大小寫、去空白）→ 更新：標題、內容、預計完成日、廠商、大分類（II-F07）；**不改**備註、小分類、TODO、追蹤、預計項目。沒有該編號 → 新增正式議題，標為「來自議題匯入」。同檔第二列撞同一編號 → 該列異常。申請者、簽核者、職級、申請／結案時間、展延時間本輪不寫入任何欄。 |
| 功能限制 | 不以標題＋廠商當識別。編號空白不匯。 |
| 注意事項 | 識別變更（舊 `TP1` 改成 `TP2`）＝舊未找到＋新新增，不自動合併。手建議題若編號碰巧等於某表單編號，視為對上並改為來自匯入（此後受唯讀規則）。 |
| 驗收條件 | 同一表單編號再匯是更新不是第二筆；標題空白列不進系統並列異常。 |

### II-F06：廠商對應與自動新增

| 項目 | 需求 |
|------|------|
| 功能目的 | 滿足正式議題廠商必填 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 廠商資訊去掉開頭「客戶名稱 :」或「客戶名稱：」（全半形冒號），再 trim。空字串 → 該列異常、不寫入。其餘：與客戶公司名稱忽略大小寫、去空白比對；對上則綁定；對不上則新增一間只有名稱的客戶公司（無窗口）並綁定。結果頁列出本次新建的公司名稱。 |
| 功能限制 | 本輪不做公司合併、不做簡稱對照表。 |
| 注意事項 | 與快捷新增廠商同一粒度（只名稱、全系統唯一）。名稱撞到既有唯一約束則綁那筆，不報錯。 |
| 驗收條件 | 主檔已有同名則不新增第二間；沒有則匯完成員頁看得到新公司；廠商欄空白的列在異常清單。 |

### II-F07：狀態對小分類

| 項目 | 需求 |
|------|------|
| 功能目的 | 用系統有無此編號、目前簽核者、工程師決定處理中；加簽／結案由使用者在結果頁逐筆判斷 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 大分類一律寫「議題」。比對姓名規則與 II-F04 相同。「簽核者」＝「目前簽核者」欄（空視為不是使用者）。工程師命中＝工程師-1 或工程師-2 命中。**狀態含「結案」**（含 `結案(通過)`、`結案(作廢)`）→ 不論新建或既有，一律寫已結案小分類，不進結果頁手動判斷。**狀態為處理中（不含結案）且工程師命中：** 系統沒有該編號 → 新增並寫處理中。系統已有、且簽核者不是使用者 → 先更新標題等欄、**不改**小分類，列入結果頁「請判斷加簽或結案」。系統已有、且簽核者是使用者 → 寫處理中。**僅 SA 命中、工程師未命中、且未結案：** 新建寫處理中；既有未結案且已有屬「議題」的小分類則不改。 |
| 功能限制 | 不依狀態名稱新建分類。不作廢單略過；作廢仍匯入並直接已結案。不做加簽保存／依小分類 ID 恢復。 |
| 注意事項 | 加簽是大分類「議題」底下的小分類，與處理中並列。未選完加簽／結案不可確認；未確認就離開則分類維持匯入前。結果頁待選清單不含已結案列。 |
| 驗收條件 | 狀態含結案一律已結案；處理中且新建工程師命中寫處理中；處理中、既有、工程師命中、簽核者不是使用者才進結果頁待選。 |

### II-F08：匯入列唯讀

| 項目 | 需求 |
|------|------|
| 功能目的 | 來自 UOF 的主資料以檔為準，網頁不手改 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 標為「來自議題匯入」的議題，詳情與任何編輯表單中：編號、標題、內容、預計完成日、廠商為**唯讀**（不可存檔改這五欄）。備註、小分類、一般 TODO、追蹤 TODO 仍可改。大分類鎖定「議題」。手建且從未對上表單編號的議題，五欄維持可改。 |
| 功能限制 | 不可在網頁把「來自匯入」改回手建以解鎖。解除唯讀的唯一路徑是未找到時選刪除。 |
| 注意事項 | 大分類畫面鎖定。下次匯入依 II-F07 寫小分類。 |
| 驗收條件 | 匯入列無法改標題並存檔；手建列仍可改標題；匯入列可改備註並存檔。 |

### II-F09：結果頁與未找到保留／刪除

| 項目 | 需求 |
|------|------|
| 功能目的 | 一次看完摘要，並處理「以前匯進來、這次沒了」 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 通過檔案檢查後寫入新增／更新，再進結果頁：摘要（新增、更新、略過未篩中、異常列、新建廠商）、**未找到**清單。未找到＝標為來自議題匯入、且編號不在本次**通過篩選的有效列**裡。手建未匯入過的議題不列。每筆未找到選保留或刪除；**必須恰好覆蓋每一筆**未找到，缺漏或多餘 → 不可結束成已處理（專案側見 II-F12）。保留＝留下並標示「本次檔案沒有」；刪除＝刪該筆及其 TODO／追蹤／預計項目（與手刪議題相同）。未確認前系統不得自動刪。 |
| 功能限制 | 結果重整後若沒了，提示重匯，不得當成已決策。 |
| 注意事項 | 結果是否持久化交 Spike。跳轉可到 `/issues/:id`。 |
| 驗收條件 | 上週匯入的編號這週篩選結果沒有 → 出現在未找到；從未匯入的手建編號不出現；未選完不能結案；選刪後列表沒有該筆。 |

### II-F10：保留標示與重新出現

| 注意事項 | 與第十二階段項次保留語意對齊，畫面不必抄同一套樣式。 |
| 驗收條件 | 保留列可辨識；同一編號再出現後標籤消失且標題已更新。 |

### II-F11：不覆蓋 TODO／追蹤／預計項目

| 項目 | 需求 |

# 五、角色權限

本輪只有**使用者本人**（單人、無登入）。

| 角色 | 可操作 |
|------|------|
| 使用者 | 匯入議題、選目前使用者與三個小分類、看結果、對未找到選保留或刪除、編輯手建議題與匯入列允許的欄（備註、分類、TODO、追蹤） |
| 公司成員／客戶窗口 | 不是操作者；成員只當「目前使用者」下拉資料，窗口本輪不使用 |

無訪客分流。開得了本機網站的人可操作本階段全部功能。

# 六、功能流程

1. 到 `/issues` → 匯入議題 → 選檔、目前使用者、三個小分類。
2. 系統讀表、篩選、對編號新增或更新、必要時新建客戶公司 → 結果頁。
3. 若有未找到：逐筆保留或刪除，選齊後結束。
4. 回到列表：匯入列五欄唯讀；保留列有標示；手建列不變。
5. 之後再匯：對上的更新；消失的再問；又出現的取消標示。

不重複第四章欄位規則。

# 七、資料需求

本輪有 Database 持久化。正式議題增量「是否來自議題匯入」「本次檔案沒有（保留標示）」。客戶公司沿用第四階段；匯入可新增只有名稱的公司。不為工時新建資料。解析用的檔案不要求永久存檔。

| 資料名稱 | 用途 | 是否持久化 | 持久化方式 | 關聯 |
|----------|------|------------|------------|------|
| 正式議題（增量） | 標示來自匯入、保留未找到、唯讀語意 | 是 | Database | 既有正式議題一筆一筆 |
| 客戶公司（既有） | 廠商必填；名稱對不上時新增 | 是 | Database | 正式議題指向一間公司 |
| 目前使用者選擇 | 下次匯入預設 | 否（本機記住即可） | 無（僅流程傳遞） | 對應一位公司成員 |
| 匯入結果（本次） | 結果頁摘要與未找到決策 | 否或短暫 | 無（僅流程傳遞） | 對應一次匯入 |

正式議題增量屬性：

| 屬性名稱 | 中文名稱 | 邏輯型態 | 驗證限制 | 是否允許空值 |
|----------|----------|----------|----------|--------------|
| 來自議題匯入 | 是否曾由本階段匯入對上 | 布林 | 新增自匯入或編號對上後為是 | 否 |
| 本次檔案沒有 | 未找到而選擇保留 | 布林 | 預設否；再出現則否 | 否 |

編號、標題、內容、預計完成日、廠商、大分類、小分類、備註仍依第一／四階段；本輪不改那些驗證。來自匯入＝是時，編號／標題／內容／預計完成日／廠商禁止經由一般編輯寫入改值。

# 八、UI／UX 需求

### 8.1 `/issues` 匯入鈕與對話

* **畫面元素：** 「匯入議題」鈕；`dialog`：檔案、目前使用者下拉、處理中小分類、已結案小分類、確定／取消。大分類固定「議題」。
* **使用者操作：** 選一個檔、選人、選三個小分類、確定。
* **系統回應：** 處理中禁用送出；成功進結果頁。
* **錯誤狀態：** 無成員、未選檔、三個小分類相同、檔案讀取失敗：頁內或 dialog 內提示，不寫入。
* **載入狀態：** 處理中文案。
* **Spike 狀態：** 待評估（UOF HTML 解析）。

### 8.2 匯入結果頁

* **畫面元素：** 摘要數字；異常列（編號／原因）；新建廠商名單；未找到列（標題、編號、查看、保留／刪除）；確認；查看開唯讀 dialog。
* **使用者操作：** 每筆未找到二選一；確認。
* **系統回應：** 決策套用後回 `/issues` 或留在結果已完成狀態。
* **錯誤狀態：** 未選完提示「請為每筆未找到資料選擇保留或刪除」。
* **載入狀態：** 重整找不到本次結果時，提示請重匯。
* **Spike 狀態：** 待評估（結果是否只放前端 state）。

### 8.3 議題詳情／列表唯讀與標示

* **畫面元素：** 五欄唯讀；保留標籤；手建列外觀不變。
* **使用者操作：** 匯入列仍可改備註、小分類、大分類、TODO。
* **系統回應：** 嘗試改唯讀欄應無法存檔或控制項不可編。
* **錯誤狀態：** 無額外權限錯誤（單人）。
* **載入狀態：** 沿用既有詳情載入。
* **Spike 狀態：** 已確認可行（既有表單改唯讀）。

# 九、非功能需求

* **效能：** 範本數百列內，篩選與寫入應在數十秒內完成；個人本機使用。
* **安全性：** 無登入；不執行檔內腳本；不把上傳檔當網站靜態檔長期公開。
* **維護性：** 議題匯入與專案 Excel 匯入分開，不要共用會混淆的同一套「工作表名稱」規則。
* **擴充性：** 之後若要工時、附件、公司合併，另開階段。
* **語系：** 繁體中文。
* **資料慣例：** 對齊 `AGENTS.md`。
* **畫面：** 粉彩 token，不改回純白／純黑。
