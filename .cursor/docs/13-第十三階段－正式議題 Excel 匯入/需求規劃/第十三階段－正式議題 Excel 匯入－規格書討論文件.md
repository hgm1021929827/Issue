### Q4：UOF「狀態」怎麼對到網頁大分類

#### 問題描述

大分類已改成使用者可自訂（種子是「預約」「議題分類」），不再固定「處理中／已完成」。範本狀態是 `處理中`、`結案(通過)`、`結案(作廢)`。小分類對不上這些字。

#### 推薦方案 A：匯入對話選兩個大分類：「進行中」與「已結案」；狀態含「結案」→ 已結案，其餘 → 進行中；小分類空白

說明：下拉預設：名稱等於或包含「議題分類／處理中」者當進行中；名稱等於或包含「已完成」者當已結案；找不到就請使用者選，不可略過。`結案(作廢)` 與 `結案(通過)` 都進已結案。再次匯入時依本次狀態覆寫大分類，小分類維持原值（原本空白就空白）。

| 面向 | 說明 |
|------|------|
| 推薦原因 | 不臆測你自訂的大分類名稱；結案語意清楚 |
| 優點 | 作廢單也進系統，可用已結案篩掉 |
| 缺點 | 第一次要選兩個大分類 |
| 開發成本 | **中**。對話多兩個下拉＋對應規則 |
| 維護成本 | **低** |

#### 其他可選方案

**方案 B：不對狀態。新列一律進預設大分類「議題分類」（沒有則第一個非預約大分類）；再次匯入不改分類**

| 面向 | 說明 |
|------|------|
| 優點 | 對話較短 |
| 缺點 | 結案單在清單裡看起來還在進行 |
| 開發成本 | **低** |
| 維護成本 | **中**。要靠手改分類 |

**方案 C：依狀態名稱自動找同名大分類；沒有就當場新建大分類**

| 面向 | 說明 |
|------|------|
| 優點 | 不必選 |
| 缺點 | 可能生出「結案(通過)」「結案(作廢)」兩個大分類，和你現有分類習慣衝突 |

### Q6：再次匯入時，哪些議題要出現在「這次檔裡沒看到」清單

#### 問題描述

第二次（或之後）匯入同一類 UOF 檔時，有些**以前匯進來的單**可能已不在這次檔裡（UOF 清單變了、篩選後沒你了、或表單編號改了）。開立規定：這種情況**不可自動刪**，要在結果頁讓你選「保留」或「刪除」。

這題只問：**哪些網頁上的議題要拿來跟這次檔比**。用例子：

- 網頁有一筆你手新增的議題，編號 `1`（從來不是 UOF 匯入的）。
- 上週匯入過 `TP260900001`、`TP260900002`。
- 這週檔裡篩選後只剩 `TP260900001`（`TP260900002` 不在這次結果裡）。

問的是：結果頁的「未找到」要不要列出 `TP260900002`？要不要連手建的 `1` 也列？

#### 推薦方案 A：只列出「曾經用 UOF 匯進來、但這次檔裡沒出現」的議題

說明：上例只列 `TP260900002`。手建的 `1` 不列、也不會被這次匯入刪掉。你選保留的，清單上加明顯標籤；選刪除的，整筆議題刪掉（TODO 一併刪，見 Q7）。表單編號改了＝舊的算未找到、新的算新增。

| 面向 | 說明 |
|------|------|
| 推薦原因 | 「這份 UOF 不見了」才問你，不會把手建單當成失踪 |
| 優點 | 誤刪手建單的風險低 |
| 缺點 | 系統要記得哪些議題來過匯入 |
| 開發成本 | **中**。要比對「來自匯入」而不只比編號字串 |
| 維護成本 | **低** |

| 面向 | 說明 |
|------|------|
| 推薦原因 | 手建單與 UOF 單分開，符合「這份檔不見了」而不是「網頁少了一筆 UOF」 |
| 優點 | 誤刪風險低 |
| 缺點 | 要記得哪些編號來過匯入（實作細節交 SA／DA） |
| 開發成本 | **中**。要比對「來自匯入」而不只比編號字串 |
| 維護成本 | **低** |

#### 其他可選方案

**方案 B：網頁上每一筆正式議題，只要沒出現在這次檔的篩選結果，都列成未找到（含手建）**
