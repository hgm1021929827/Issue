# 第十三階段－正式議題 Excel 匯入－階段開立紀錄

**角色：** WFM  
**日期：** 2026-09-05  
**類型：** 階段開立（治理；非需求、非技術設計）

本文件凍結本階段流程與範圍邊界。不寫功能欄位、API 或 Schema。

## 一、開立依據

- 使用者指示：實作「正式議題 Excel 匯入」；指定流程管理助手開立新階段。
- [開發階段總覽](../../開發階段總覽.md)：第十二階段「專案工作項次與工時」已結案。該階段只匯專案 `P-*.xlsx` 的「工作項目」「議題單」；[議題匯入範本.xls](../../../../Template/議題匯入範本.xls) 留給之後階段。
- 第十二階段開立紀錄已將「正式議題匯入（`議題匯入範本.xls`／UOF HTML）」列為本輪不做。
- 原始需求 [個人工作追蹤網頁需求修正與新增內容.pdf](../../../../docs/個人工作追蹤網頁需求修正與新增內容.pdf) 第五～八章是**專案** Excel，不是正式議題匯入。本階段準據以範本檔與既有正式議題模型為主；專案匯入規則只當對照，不得直接套用。
- 第一、三～十二階段正式文件不覆寫。第二階段粉彩視覺仍進行中（規格已確認、頁面已套用）；本階段不結案第二階段。

## 二、範圍凍結

| 本階段做 | 本階段不做（留給之後新階段） |
|----------|------------------------------|
| 從 `議題匯入範本.xls`（UOF HTML）匯入**正式議題**（第一階段議題實體，不是專案議題） | 加簽狀態保存與恢復、加簽大分類 |
| 依「目前使用者」篩選後新增或更新 | 預約連線 CRUD／清單／行事曆 |
| 再次匯入差異：本次未找到不得自動刪；使用者選保留或刪除 | 臨時工作、登入／權限、回收筒 |
| 匯入結果頁（摘要、異常、跳轉） | 專案 `P-*.xlsx` 其他工作表（查核點、CheckList、議題圖等） |
| 備註工時／列複核：僅當範本確有對應欄才納入（有無、規則交 PM） | 把第四階段歷史「專案 Excel」規格當本輪現行規格直接實作 |
| | Q-12-02（刪分類是否計工作項次；規格對齊，與本功能無關） |

欄位細節、唯一識別、篩選欄、廠商／分類對應、畫面入口：交 PM《規格書討論文件》勾選，WFM 不定案。

Q-12-01（專案 `import-decisions` 空陣列仍 200）**不凍結進本階段必做**；PM 可勾選是否本輪順手修。

已知約束（前階段已確認、本輪不得推翻為登入系統）：

- 第一階段 Q3＝A：單人、無登入；成員與客戶是**通訊錄資料**，不是帳號。
- 第十二階段已用「匯入下拉選目前使用者、記住上次」；本輪可對照，不得改成登入帳號。
- 第四階段：正式議題廠商必填；公司成員與客戶窗口兩套主檔。
- 正式議題既有欄位：編號、標題、內容、分類、預計完成日、備註（第一階段）；列表在 `/issues`（第十階段）。
- 第十二階段 ClosedXML **只讀 `.xlsx`**。本輪檔案是 `.xls`／UOF HTML，**必須重做 Tech Spike**，不得假設沿用 ClosedXML。
- 專案匯入畫面（匯入對話、結果頁）可當對照，畫面落點交 PM，WFM 不指定。
- 第四階段改範圍前的 Excel 原稿見 [歷史資料說明](../../04-第四階段－成員與廠商/歷史資料/說明.md)，**不得當本輪現行規格直接實作**。

已知缺口（PM 必須先討論，不可因總覽有標題就跳過）：

- `.xls`／UOF HTML 怎麼讀、一次一檔是否沿用
- 正式議題唯一識別（既有編號或其他範本欄）
- 篩選欄位、廠商／分類如何對上既有主檔（缺廠商怎麼辦）
- 未找到列的操作時機與畫面；識別變更是否＝舊未找到＋新新增
- 網頁已有一般 TODO／追蹤 TODO 是否不被 Excel 覆蓋
- 入口（`/issues` 是否對齊專案清單「匯入 Excel」）
- 範本有無備註工時可解析
- 是否本輪順手修 Q-12-01

## 三、約束（各角色皆須遵守）

- **不改**第一～十二階段正式文件。本輪用增量接上。
- **不得**把第四階段歷史資料裡的專案 Excel 規格／設計／DA 原稿當本輪現行規格直接實作。
- **不得**把原始 PDF 第五～八章（專案 Excel）當成正式議題匯入正文。
- **技術棧**維持 React（Vite）+ ASP.NET Core 9 + MySQL；不要換框架。
- **新畫面**對齊第二階段《視覺設計規格書》（奶油白底、霧藍主色、棕灰文字、大圓角淺陰影）。
- 使用者可見文案使用繁體中文。
- 日常交付不經 WFM 關卡。
- 需求類型 ①，RD Tech Spike **必做**（`.xls`／UOF HTML 解析）。舊 ClosedXML Spike 可參考，不得假設本輪可直接沿用。
