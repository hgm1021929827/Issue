# 一～二

正式議題詳情複用 `WorkHourTable`。`work_hour` 增加第三歸屬 `issue_id`。API 掛 `/issues/{id}/hours`。不寫 `issue` 完成／實際日欄。不改 Excel 匯入。

# 三、流程

1. 載入既有議題時一併 `GET /issues/{id}/hours`。
2. 新增／更新／刪除後 API 回傳該議題完整工時列表；前端以列表加總顯示合計。
3. 同日衝突 → `code` 409「同一日已有工時」。
4. 時數／日期／備註驗證對齊第十二階段（400）。
5. 刪議題時一併刪除其工時列。

# 四、API

| 方法 | 路徑 | Body | `data` |
|------|------|------|--------|
| GET | `/issues/{id}/hours` | — | `WorkHour[]` |
| POST | 同上 | `{ date, hours, remark? }` | `WorkHour[]`（整表） |
| PUT | `/issues/{id}/hours/{hourId}` | 同上 | `WorkHour[]` |
| DELETE | 同上 | — | `WorkHour[]` |

`WorkHour`：`{ id, date, hours, remark }`。歸屬只由路徑決定，JSON 不含 FK。

# 五～六

- `api.issueHours`／`createIssueHour`／`updateIssueHour`／`deleteIssueHour`
- `IssuePage`：非新建時掛 `WorkHourTable`（表單與 `TrackTodoList` 之間）
- 複用既有 `.hours-card` 樣式

# 七、邏輯模型

`WorkHour` 加 `IssueId`（可空）。三者恰一非空：`ProjectWorkItemId`｜`ProjectIssueId`｜`IssueId`。`hoursTotal` 不存欄。
