## 三、issue_todo（加欄）

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| issue_id | 正式議題歸屬 | BIGINT | FK → issue | 是 | NULL | 與 work_item 恰一有值 |
| project_work_item_id | 工作項次歸屬 | BIGINT | FK → project_work_item | 是 | NULL | 與 issue 恰一有值 |

C#：`IssueTodo.IssueId`、`IssueTodo.ProjectWorkItemId`。

CHECK `ck_issue_todo_owner`：

```
(issue_id IS NOT NULL AND project_work_item_id IS NULL)
OR (issue_id IS NULL AND project_work_item_id IS NOT NULL)
```

索引：`ix_issue_todo_work_item`（`project_work_item_id`, `parent_todo_id`, `sort_order`）。既有（`issue_id`, `parent_todo_id`, `sort_order`）保留。

FK：`fk_issue_todo_work_item` → `project_work_item(project_work_item_id)`。MySQL `ON DELETE CASCADE`；SQL Server 不設 CASCADE，刪項次前應用層先刪待辦。`issue_id` 既有 FK 語意維持 Restrict／既有行為。

既有列：`project_work_item_id` 為 NULL，`issue_id` 仍有值。

## 四、遷移注意

Seeder：加欄 → `issue_id` 改可空 → 加索引／FK → ADD CHECK。EF `EnsureCreated` 新庫直接可空＋雙 FK Restrict。
