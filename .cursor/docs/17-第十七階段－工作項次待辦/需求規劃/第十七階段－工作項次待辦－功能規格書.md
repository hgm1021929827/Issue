**角色：** PM  
**版本：** v1.0  
**日期：** 2026-09-17  
**狀態：** 需求規劃完成；交 SA  
**需求類型：** ① Web 應用（含 UI／API，需 Database 增量）  
**來源：** 使用者確認兩項：工作項次要有待辦；新增待辦時一起填標題與內容。重開第十二階段已拒絕之「工作項次一般 TODO 樹」。對齊第一階段 WT-F04／F05。  

確認紀錄：範圍＝工作項次＋共用新增表單；專案／專案議題待辦、預約不在本輪。

---

# 一、專案介紹

工作項次右側目前只有工時與需要追蹤的 TODO。本階段把正式議題的多層「待辦」掛到工作項次，並修正新增只能填標題、內容要再點選才出現的操作。

# 二、專案目標

1. 工作項次詳情可維護與議題相同的待辦樹（多層、同層拖曳、父項自動完成）。
2. 新增根項或子步驟時，表單同時有標題（必填）與內容（可空），送出即寫入。
3. 刪工作項次／刪專案／匯入結果刪項次時連刪待辦；Excel 匯入不覆蓋待辦。
4. 議題頁待辦沿用同一元件，新增體驗一併改。

# 三、產品定位

| 欄位 | 說明 |
|------|------|
| **本期範圍** | 工作項次待辦 CRUD 與樹規則；新增表單標題＋內容；刪除連刪；compact 單欄 |
| **不在範圍** | 專案／專案議題待辦；待辦上行事曆；拖曳改掛父項；預約連線；手新增工作項次 |

# 四、功能需求

### WI-T01：工作項次待辦樹

| 項目 | 需求 |
|------|------|
| 功能目的 | 在工作項次拆步驟，規則與正式議題待辦相同 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 專案詳情「工作項次」tab，選一筆後右側（工時、追蹤 TODO 旁）出現「待辦」。可新增根項與子步驟、勾選完成、編輯、刪除（含子樹）、同層拖曳。父項自動完成對齊 WT-F05。 |
| 功能限制 | 不可拖曳改掛父項。不上行事曆。專案內容／專案議題本輪無待辦。工作項次右欄用單欄 compact，不再套議題頁雙欄。 |
| 驗收條件 | 可建至少三層；同層排序保存後仍在；跨層拖曳不改歸屬；刪父連刪子孫；標題空白不可存。 |

### WI-T02：新增時標題與內容

| 項目 | 需求 |
|------|------|
| 功能目的 | 建立待辦不必先存標題再點進去補內容 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 新增根項或子步驟：標題必填、內容可空，送出後兩欄皆寫入。之後仍可點選列編輯。議題詳情待辦同一套。 |
| 功能限制 | 內容可不填（空字串）。不改標題長度／內容長度上限。 |
| 驗收條件 | 新增時填了內容，列表或詳情看得到，不必第二次儲存。只填標題仍可新增。 |

### WI-T03：刪除與匯入

| 項目 | 需求 |
|------|------|
| 功能目的 | 待辦跟隨工作項次生命週期；匯入不洗掉 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 刪單筆工作項次、刪專案、匯入未找到而選刪：連刪該項次待辦。再次匯入更新項次主資料時不新增／不改／不刪待辦。 |
| 驗收條件 | 刪項次後再 GET todos 為 404 或空且庫無列；匯入後既有待辦仍在。 |

# 五、資料欄位

待辦列：是否完成、標題（必填，≤200）、內容（可空，≤2000）、排列順序、父項。歸屬恰好為正式議題 **或** 工作項次之一。

# 六、未來規劃

專案／專案議題待辦、預約連線處理事項掛待辦。
