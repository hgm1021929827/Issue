# 第四階段－專案 Excel 匯入－階段開立紀錄

**角色：** WFM  
**日期：** 2026-09-02  
**類型：** 階段開立（治理；非需求、非技術設計）  
**需求類型：** ① Web 應用  

本文件凍結本階段流程與範圍邊界。不寫功能欄位、API 或 Schema。

---

## 一、開立依據

- 使用者確認第三階段測試結案後，同意下一輪做「專案 Excel 匯入」這一串，**不**一次做完全部剩餘功能。
- 第一階段《功能規格書》第十章「下一階段」中，專案／專案議題已由第三階段交付；本輪承接：Excel 匯入、工作表規則、日期工時、Excel 備註工時比對、匯入異常與跳轉。
- 第三階段正式文件不覆寫。第二階段粉彩視覺仍進行中（規格已確認、頁面已套用）；本階段不結案第二階段。

---

## 二、範圍凍結

| 本階段做 | 本階段不做（留給之後新階段） |
|----------|------------------------------|
| 專案 Excel 匯入 | 臨時工作 |
| 工作表規則（工作項目／議題單是否存在） | 成員維護、客戶公司／窗口 |
| 日期工時；匯入可選文字過濾負責人員／處理人 | 依成員主檔篩選（無成員實體） |
| Excel 備註工時比對 | 廠商下拉與快捷新增廠商 |
| 匯入異常與跳轉 | 加簽恢復、預約連線、正式議題綁專案、登入、回收筒 |

欄位對應、覆蓋規則、工時如何落在專案／專案議題、缺表是否整批停止：交 PM《規格書討論文件》勾選，WFM 不定案。

已知缺口：來源第五章匯入前置把**廠商**當必填，且 6.1／6.2 依人員篩選。本輪不做成員／廠商，討論文件必須讓使用者勾選「如何略過」而不能臆測成已有成員系統。

- **不改**第一、三階段正式文件。
- **技術棧**維持 React（Vite）+ ASP.NET Core 9 + MySQL；不要換框架。

- 日常交付不經 WFM 關卡。
