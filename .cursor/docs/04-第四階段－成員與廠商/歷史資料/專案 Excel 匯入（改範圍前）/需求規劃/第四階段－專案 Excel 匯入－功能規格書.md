# 一、專案介紹

本階段讓使用者把固定格式的 **Excel** 匯入**既有一筆專案**：工作表「工作項目」每一列成為該專案底下獨立的**工作項目**；「議題單」對應第三階段的**專案議題**。系統保存**日期工時**，與 Excel 備註工時、實際起迄比對，並在匯入結果與專案詳情提示異常。

不做臨時工作、成員主檔、客戶公司／廠商、登入。負責人員／處理人僅作匯入時可選的**文字過濾**。

# 二、專案目標

1. 在已選專案上傳一份 `.xlsx`：必須有「工作項目」「議題單」兩張表；缺表或工作項目沒有任何有效列則**整批不寫入**；議題單可以是空表。
2. 可選填負責人員、處理人字串，有填才過濾對應工作表列（忽略大小寫、去前後空白）。
3. 工作項目列 upsert 成獨立實體；專案議題依項次 upsert；網頁多出來的列**不因匯入刪除**。
4. 專案、工作項目、專案議題皆可維護日期工時；備註格式 `6/12 - 3H`（可沒有年，用匯入當下西元年）。
5. 實際開始隨工時自動取最早日；實際結束僅在「標記完成」時寫入。Excel 實際日空白不得覆蓋網頁已有值。
6. 每次匯入有結果頁（摘要、異常、跳轉）；專案／工作項目／專案議題詳情對實際日缺口顯示橫幅。

| 項目 | 需求 |
|------|------|
| 功能目的 | 網頁側持久化逐日工時，供比對與實際起迄 |

### EX-F08：備註工時解析與比對

| 項目 | 需求 |
|------|------|
| 功能目的 | 把 Excel 備註逐日解析，並與網頁日期工時比對 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 備註可多行。每行符合 `M/D - 數字H`（`H`／`h` 皆可；數字可小數；日期可 `M/D` 或 `YYYY/M/D`）。省略年時用**匯入當下的西元年**。無法解析的行：列入異常，不寫入該行；其餘行與其他列照常。比對（工作項目對工作項目、專案議題對專案議題）：網頁有該日 Excel 無；Excel 有該日網頁無；同日小時不同；無法解析。專案本體若本次匯入沒有對應備註來源，不對專案本體做備註比對（專案工時以工作項目列為準）。 |
| 功能限制 | 不支援其他單位（人天、分鐘）。壞行不造成整份失敗（除非 EX-F02 已整批停）。 |
| 注意事項 | 來源 8.1／8.2 的四種提醒都要能出現在結果頁。 |
| 驗收條件 | `6/12 - 3H` 寫入匯入年該日 3 小時；`6/15 - 2.5H` 寫入 2.5；亂碼行列異常且其他行成功；同日網頁 1H、Excel 3H 列為不同。 |

### EX-F09：預計日寫回與實際起迄、標記完成

| 項目 | 需求 |
|------|------|
| 功能目的 | 計畫日以 Excel 有值為準更新；實際日由工時與標記完成計算，Excel 空白不覆蓋 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | **預計開始／完成：** Excel 該欄有值 → 更新對應專案議題或工作項目（專案本體預計日：僅當工作項目表有「專案級」預計欄且 SA 對照得到單一值時才更新專案；若只有列級預計日則只寫該工作項目）。空白不覆蓋。兩邊都有但不同 → 寫成 Excel 值，結果列出「預計日已改為來源值」。起迄都有值時開始不可晚於完成，違者該列異常不寫該列預計日。**實際開始：** 永遠＝該主體日期工時最早日（無工時則空）。專案的實際開始＝專案本體工時與**其下所有工作項目**工時的最早日。**標記完成／取消完成：** 專案、工作項目、專案議題各有此操作（不寫死小分類名稱）。標記完成時實際結束＝當時該計算範圍最後一筆工時日（專案範圍同實際開始）；無工時則不可標記並提示。取消完成則清空實際結束，不刪工時。標記後再加工時**不**自動改實際結束。**Excel 實際開始／結束空白**且網頁已有值：不覆蓋，結果列異常，詳情橫幅至下次匯入該欄有值（EX-F10）。Excel 實際欄有值且與網頁不同：本輪**不拿 Excel 實際日覆蓋**網頁計算值，只列異常（網頁計算為準）。 |
| 功能限制 | 標記完成不是改大分類、也不是第三階段小分類的替代；兩者並存。無回收筒。 |
| 注意事項 | 第三階段「完成靠小分類」仍適用分類色標；本輪「標記完成」只為實際結束日。 |
| 驗收條件 | 預計日空白不刪網頁日；有值則更新。未標記完成時實際結束為空。標記完成後實際結束等於當時最後工時日；再新增更晚工時不改實際結束。Excel 實際欄空白不把網頁實際日清掉。 |

# 五、角色權限

本輪只有**使用者本人**（單人、無登入）。開到本機網站即可匯入與改工時。無訪客分流。

# 六、功能流程

1. 使用者以第三階段功能建立或選取專案 → 詳情點匯入。
2. （可選）填負責人員、處理人 → 選 `.xlsx`。
3. 系統驗表 → 失敗則整批停、資料不變。
4. 通過則 upsert 工作項目與專案議題、寫入日期工時、比對備註與實際日規則 → 結果頁。
5. 使用者可從結果跳轉改工時、標記完成、或再匯入。
6. 日常不匯入時，仍可在詳情手改日期工時與標記完成。

後續階段才接入：成員主檔篩選、廠商必填、臨時工作、一份檔多專案。

# 七、資料需求

本輪有 Database 持久化。既有專案、專案議題、分類繼續使用，並新增工作項目、日期工時、完成標記與實際起迄。

### 7.1 資料清單

| 資料名稱 | 用途 | 是否持久化 | 持久化方式 | 關聯 |
|----------|------|------------|------------|------|
| 專案（既有增量） | 匯入容器；本體也可有工時與標記完成 | 是 | Database | 一對多工作項目、專案議題、日期工時 |
| 工作項目 | Excel「工作項目」列對應的工作包 | 是 | Database | 必屬一筆專案；可有分類；一對多日期工時 |
| 專案議題（既有增量） | Excel「議題單」 | 是 | Database | 不變；加日期工時與標記完成 |
| 日期工時 | 某日的小時數 | 是 | Database | 必屬專案或工作項目或專案議題恰好一個 |
| 大分類／小分類（既有） | 工作項目可選，規則同專案 | 是 | Database | 刪分類檢查須含工作項目 |

# 八、UI／UX 需求

視覺對齊第二階段。Spike：Excel 解析與表頭別名、同日標記擁擠若含工作項目。

### 8.1 匯入對話

* **畫面元素：** 選檔、負責人員、處理人、確定／取消（`dialog`）。
* **使用者操作：** 填過濾、選 `.xlsx`、送出。
* **系統回應：** 成功進結果頁；整批失敗橫幅或結果頁只顯示失敗原因。
* **錯誤狀態：** 非 xlsx、缺表、工作項目零列、代號不符。
* **載入狀態：** 上傳／解析中不可重送。
* **Spike 狀態：** 待評估（檔案大小、表頭別名容錯）。

### 8.2 匯入結果頁

* **畫面元素：** 摘要筆數、異常列表、跳轉按鈕。
* **使用者操作：** 點跳轉、回專案詳情。
* **系統回應：** 進專案詳情並定位工作項目或專案議題。
* **錯誤狀態：** 無。
* **載入狀態：** 結果已在當次回應中。
* **Spike 狀態：** 已確認可行。

### 8.3 專案詳情增量

* **畫面元素：** 匯入入口；工作項目列表（與專案議題分區）；日期工時區；標記完成；實際起迄唯讀；7.2 橫幅。
* **使用者操作：** 匯入、CRUD 工作項目、改工時、標記／取消完成。
* **系統回應：** 列表與實際日起更新。
* **錯誤狀態：** 工時同一日重複、無工時卻標記完成。
* **載入狀態：** 載入中。
* **Spike 狀態：** 已確認可行。

### 8.4 行事曆

* **畫面元素：** 到期日視角加上有預計完成日的**工作項目**標記，須能與專案、專案議題區分。
* **使用者操作：** 點標記進專案並定位該工作項目。
* **系統回應：** 同第三階段到期日視角。
* **錯誤狀態：** 載入失敗提示。
* **載入狀態：** 同現況。
* **Spike 狀態：** 待評估（四種來源同格擁擠）。

# 九、非功能需求

* **效能：** 單次匯入建議可處理約數百列工作項目＋議題於數十秒內；超出可失敗並提示檔太大（上限由 SA 定一個合理值）。
* **安全性：** 不執行檔內巨集；只讀儲存格值。
* **維護性：** 表頭別名集中一處，方便改名。
* **擴充性：** 之後成員主檔可取代文字過濾，不改工作項目／專案議題唯一鍵。
* **語系：** 繁體中文。用詞：「工作項目」「專案議題」「正式議題」須區隔。
