# 一、專案介紹

本階段新增**通訊錄**：公司成員、客戶公司與窗口（含多筆聯絡）。專案與正式議題必須選擇廠商（客戶公司）；專案可選填負責人員（公司成員）。專案議題不另選廠商、不選處理人，廠商跟所屬專案。

成員與客戶不是帳號，沒有登入。不做 Excel、追蹤 TODO、預約連線。

# 二、專案目標

1. 導覽「成員」一頁兩個頁籤：公司成員、客戶窗口（公司→窗口→聯絡）。可增查改刪；名稱關鍵字過濾。
2. 公司成員有中文名、英文名、備註；中文名可重複。客戶公司名稱全系統唯一；同一公司下窗口名稱不可重複。
3. 新增或儲存專案、正式議題時，廠商必填。表單旁可快捷新增客戶公司（只填名稱，自動選取）。
4. 專案可選填負責人員（公司成員下拉）。正式議題與專案議題不選處理人。
5. 刪成員、客戶公司前檢查本輪引用；有引用則禁止並顯示筆數。刪公司會連同窗口與聯絡。

# 五、角色權限

本輪只有**使用者本人**（單人、無登入）。公司成員與客戶窗口不是操作者，只是資料。

# 六、功能流程

1. 使用者在「成員」建立客戶公司（或之後在表單快捷新增），必要時再補窗口與聯絡。
2. 可建立公司成員（中文名＋英文名）。
3. 新增或補存專案／正式議題時必選廠商；專案可再選負責人員。
4. 專案議題仍只在專案底下維護，廠商看專案。
5. 刪通訊錄前系統數本輪引用，有則擋。

後續階段才接入：Excel 依成員／廠商篩選或改必填語意、追蹤 TODO、預約連線。

# 八、UI／UX 需求

視覺對齊第二階段。

### 8.1 成員維護頁

* **畫面元素：** 導覽「成員」；兩 tab；關鍵字；公司成員表（中文名、英文名、備註）；客戶公司列表與展開之窗口／聯絡；新增／編輯 dialog；刪除確認 dialog。
* **使用者操作：** 切 tab、搜尋、增改刪。
* **系統回應：** 列表替換；刪除失敗橫幅含筆數。
* **錯誤狀態：** 驗證、名稱重複、使用中不可刪。
* **載入狀態：** loading／empty／data。
* **Spike 狀態：** 待評估（公司＋窗口＋聯絡同屏是否擁擠）。

### 8.2 專案／正式議題表單增量

* **畫面元素：** 廠商下拉（必填標記）；快捷新增鈕；專案另有負責人員下拉（可空）。專案議題唯讀廠商文字。
* **使用者操作：** 選廠商、快捷新增、選負責人員。
* **系統回應：** 快捷新增後自動選取。
* **錯誤狀態：** 未選廠商不可存；快捷名稱重複。
* **載入狀態：** 下拉載入中。
* **Spike 狀態：** 已確認可行。

# 九、非功能需求

* **效能：** 通訊錄以數百筆為準，一次載入列表即可。
* **安全性：** 無登入；不把成員當帳號。
* **維護性：** 聯絡類型集中一處列舉。
* **擴充性：** 之後追蹤／預約可重用客戶公司與窗口，不改本輪唯一鍵。
