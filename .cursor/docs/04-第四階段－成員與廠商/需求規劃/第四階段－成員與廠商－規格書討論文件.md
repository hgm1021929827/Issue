- Excel 規格已從本階段正式文件拿下，全文在歷史資料。本輪若專案綁了廠商、工作綁了人，之後匯入才能改「必填廠商／依成員篩選」；本輪**不實作匯入**。

### Q1：公司成員與客戶窗口是不是兩套資料

#### 問題描述

來源第九章把「公司成員」和「客戶公司＋窗口」分成兩個頁籤。有沒有可能把所有人都做成同一種「聯絡人」，再用類型區分？

#### 推薦方案 A：兩套主檔，對齊來源（公司成員平鋪；客戶為公司→窗口）

說明：內部同事只有名稱清單。外部是客戶公司底下才有窗口。之後追蹤／預約的兩個下拉（對象類型 → 實際對象）才能直接對上。

| 面向 | 說明 |
|------|------|
| 推薦原因 | 對齊第九章與 2.2；內部與外部不會混在同一下拉 |
| 優點 | 下輪追蹤、預約、Excel 負責人／處理人不必再拆模型 |
| 缺點 | 兩套 CRUD、兩種刪除檢查 |
| 開發成本 | **中**。兩套實體與一個雙頁籤畫面 |
| 維護成本 | **低**。界線與來源一致 |

#### 其他可選方案

**方案 B：同一套「人」，用類型標記內部／客戶**

| 面向 | 說明 |
|------|------|
| 優點 | 一個維護頁、一種人 |
| 缺點 | 來源的「客戶公司」層不見了；窗口職位／多筆聯絡與內部成員欄位會互相遷就；2.2 第二層下拉不好做 |
| 開發成本 | **中**。表面少表，語意要自己發明 |
| 維護成本 | **高**。與第九章、預約窗口過濾不一致 |

**方案 C：本輪只做客戶公司（廠商），公司成員下一輪**

| 面向 | 說明 |
|------|------|
| 優點 | 較小；先滿足專案綁廠商 |
| 缺點 | 你點名的是「成員／廠商」整包；內部成員仍沒有主檔 |
| 開發成本 | **低**。少一套 CRUD |
| 維護成本 | **中**。很快又要再做成員頁 |

#### 建議選擇

> 建議選擇 **A**。

原因：來源第九章與 2.2 已經把兩套分開；合一會讓之後追蹤／預約很難接。

#### 使用者選擇

☑ A — 兩套主檔：公司成員＋客戶公司／窗口（推薦）

□ B — 同一套聯絡人，用類型區分

□ C — 本輪只做客戶公司，公司成員下一輪

### Q7：客戶窗口與聯絡資料做到哪裡

#### 問題描述

來源：窗口有名稱、職位；聯絡資料多筆，每筆「聯絡類型＋聯絡內容」，例子含電話、手機、Email、Teams、其他。公司與窗口都要 CRUD。

#### 推薦方案 A：完整照第九章：公司名稱；窗口名稱＋職位；每窗口多筆聯絡（類型＋內容）

說明：聯絡類型用固定選項（電話、手機、Email、Teams、其他），內容為字串。公司名稱全系統唯一（忽略大小寫）。同一公司下窗口名稱不可重複。職位可空。

| 面向 | 說明 |
|------|------|
| 推薦原因 | 本輪目標就是成員／廠商主檔；少做一截下輪還要補表 |
| 優點 | 預約／追蹤需要窗口時資料已在 |
| 缺點 | 編輯畫面層次多（待 Spike） |
| 開發成本 | **中**。巢狀清單＋dialog |
| 維護成本 | **中**。類型若以後要加項再擴 |

#### 其他可選方案

**方案 B：窗口只有名稱＋職位，本輪不做多筆聯絡**

| 面向 | 說明 |
|------|------|
| 優點 | 較快 |
| 缺點 | 第九章一半沒做；聯絡仍要再一輪 |
| 開發成本 | **低** |
| 維護成本 | **中** |

**方案 C：窗口壓成單筆電話＋單筆 Email 兩個欄位**

| 面向 | 說明 |
|------|------|
| 優點 | 表單扁、好填 |
| 缺點 | 沒有 Teams／多支電話；之後難遷成多筆 |
| 開發成本 | **低** |
| 維護成本 | **高**。結構與來源不同 |

#### 建議選擇

> 建議選擇 **A**。

原因：你選的是成員／廠商整包；聯絡多筆是第九章本體，不是附加。

#### 使用者選擇

☑ A — 公司／窗口／多筆聯絡都做（推薦）

□ B — 窗口只做到名稱＋職位

□ C — 窗口改成單一電話＋Email 欄位

□ 自行補充

### Q8：專案／專案議題要不要選「負責人員／處理人」（公司成員）

#### 問題描述

來源完整專案主資料有「負責人員」；議題單依「處理人」篩選。第三階段都沒有這些欄。先前 Excel 討論曾用**文字框**過濾（因為當時沒有成員主檔）；該稿在歷史資料。本輪若做成員卻不掛到工作上，匯入仍只能對字串。

#### 推薦方案 A：專案可選填負責人員、專案議題可選填處理人，都指向公司成員，可空

說明：下拉公司成員，不是自由輸入。本輪不做 Excel；歷史資料中的文字過濾規格等實作匯入時再改成比對成員。正式議題本輪不加人（來源負責人員寫在專案主資料）。

| 面向 | 說明 |
|------|------|
| 推薦原因 | 成員主檔要被工作用到才有意義；可空不擋舊資料 |
| 優點 | 之後匯入篩選可對 ID 或標準姓名 |
| 缺點 | 專案／專案議題表單各多一個下拉 |
| 開發成本 | **低**。兩個可空參照 |
| 維護成本 | **低** |

#### 其他可選方案

**方案 B：本輪工作都不綁人，只有通訊錄**

| 面向 | 說明 |
|------|------|
| 優點 | 範圍更小 |
| 缺點 | 成員頁與專案仍脫鉤；Excel 仍只能對自由文字 |
| 開發成本 | **低** |
| 維護成本 | **中** |

**方案 C：可選成員，也可改填自由文字（兩種並存）**

| 面向 | 說明 |
|------|------|
| 優點 | 還沒建檔的人名仍能先寫 |
| 缺點 | 同一欄兩種來源，匯入比對會亂 |
| 開發成本 | **中** |
| 維護成本 | **高** |

#### 建議選擇

> 建議選擇 **A**。

原因：有主檔就用下拉；可空即可。不要再做一套自由文字和成員並存。

#### 使用者選擇

☑ A — 專案負責人員、專案議題處理人改選公司成員，可空（推薦）

□ B — 本輪工作不綁人

□ C — 成員下拉與自由文字並存

□ 自行補充（採 A 的專案負責人員；正式議題與專案議題都不選處理人）

### Q9：刪成員／公司／窗口時，本輪檢查哪些占用

#### 問題描述

來源：成員刪前檢查追蹤 TODO 或其他；公司／窗口刪前檢查議題、專案、追蹤 TODO、預約。本輪沒有追蹤與預約實體。若 Q2／Q3／Q8 有綁定，那些引用必須擋刪。

#### 推薦方案 A：只檢查本輪實際存在的引用；有引用則禁止刪並顯示筆數

說明：

- 客戶公司：被專案或正式議題的廠商引用則不可刪。
- 窗口：本輪若無工作直接指向窗口，則只要沒有「本輪做出來的引用」即可刪；若之後預約／追蹤才指向窗口，本輪刪窗口不查那些（實體尚不存在）。刪公司時一併刪其窗口與聯絡（dialog 說明）。
- 公司成員：被專案負責人員或專案議題處理人引用則不可刪（若 Q8＝B 則成員刪除無工作引用）。
- 聯絡資料：隨窗口刪，或可單筆刪聯絡。

| 面向 | 說明 |
|------|------|
| 推薦原因 | 不虛構追蹤／預約表來做 COUNT；有綁就擋 |
| 優點 | 與第三階段刪分類「使用中顯示筆數」同一套體驗 |
| 缺點 | 現在刪掉的窗口，下輪做預約時不會有歷史占用（本輪本來就沒預約） |
| 開發成本 | **低**。COUNT 現有綁定 |
| 維護成本 | **低**。下輪加追蹤／預約時再擴大 COUNT |

#### 其他可選方案

**方案 B：一律允許刪，綁定欄位自動清空**

| 面向 | 說明 |
|------|------|
| 優點 | 不會刪不掉 |
| 缺點 | 專案廠商默默消失，沒有確認 |
| 開發成本 | **低** |
| 維護成本 | **中**。資料 silently 斷線 |

**方案 C：本輪禁止刪除公司成員與客戶公司（只能改名）**

| 面向 | 說明 |
|------|------|
| 優點 | 最安全 |
| 缺點 | 建錯也刪不掉，超出來源（來源要求能刪） |
| 開發成本 | **低** |
| 維護成本 | **中** |

#### 建議選擇

> 建議選擇 **A**。

原因：對齊來源「使用中不可刪」，但只數得到的表；不要為了還沒做的預約先建空表。

#### 使用者選擇

☑ A — 有本輪引用就禁止刪，並顯示筆數（推薦）

□ B — 可刪，引用自動清空

□ C — 成員與客戶公司本輪不能刪

□ 自行補充

### Q10：成員維護怎麼進、查詢做到哪

#### 問題描述

來源第十五章要有「成員維護－公司成員／客戶窗口」。9.1／9.2 寫需支援查詢。尚未定義查詢是關鍵字還是進階篩選。

#### 推薦方案 A：導覽新增「成員」；一頁兩個頁籤；名稱關鍵字過濾即可

說明：Tab 公司成員、Tab 客戶窗口（先列公司，點進或展開看窗口與聯絡）。查詢是該 tab 上方一個關鍵字（成員名稱／公司名稱／窗口名稱）。刪除用 `dialog` 確認。

| 面向 | 說明 |
|------|------|
| 推薦原因 | 對齊第十五章一個入口、兩個頁籤；個人通訊錄不需要進階報表 |
| 優點 | 找得到、改得到 |
| 缺點 | 不能依聯絡電話反查 |
| 開發成本 | **中**。新頁＋雙 tab＋列表 |
| 維護成本 | **低** |

#### 其他可選方案

**方案 B：兩個獨立導覽項目（公司成員、客戶公司）**

| 面向 | 說明 |
|------|------|
| 優點 | 少 tab 切換 |
| 缺點 | 導覽變擠；與第九章「一頁兩 tab」不符 |
| 開發成本 | **中** |
| 維護成本 | **低** |

**方案 C：不做獨立頁；只在專案／議題表單的下拉裡快捷新增與即時建立**

| 面向 | 說明 |
|------|------|
| 優點 | 少一頁 |
| 缺點 | 查詢、改窗口聯絡、刪除檢查都難做；對不齊第九章 |
| 開發成本 | **低**（維護能力不足） |
| 維護成本 | **高** |

#### 建議選擇

> 建議選擇 **A**。

原因：來源就是一個成員維護頁兩個頁籤；關鍵字過濾夠用。
