# 二、模組拆分

| 模組 | 職責 |
|------|------|
| 公司成員 | CRUD；供專案負責人員下拉 |
| 客戶公司 | CRUD；供廠商下拉與快捷新增 |
| 客戶窗口／聯絡 | 隸屬公司的巢狀 CRUD |
| 專案（既有增量） | 寫入必填 `clientCompanyId`；可選 `ownerMemberId` |
| 正式議題（既有增量） | 寫入必填 `clientCompanyId` |
| 專案議題 | 不新增欄；詳情帶出專案廠商名稱 |

前端：導覽「成員」、`/members` 雙 tab。專案／議題表單加下拉。

# 三、功能流程

- **寫入必填廠商：** `POST`／`PUT` 專案或正式議題時 `clientCompanyId` 必填且須存在。舊列資料庫可暫 null；`GET`／列表仍回傳，`clientCompanyId` 為 null。前端儲存前擋空值。
- **快捷新增：** `POST /client-companies` 成功後前端把回傳 `id` 填進表單，不必再開一次列表 API（也可再拉列表）。
- **專案議題：** 回應帶 `clientCompanyId`／`clientCompanyName`（從專案帶出，唯讀）。寫入 DTO 不含這兩欄。
- **刪除：** 應用層 COUNT 後 409。刪公司時服務層先確認無專案／議題引用，再刪窗口與聯絡（或 CASCADE）。
- **成員下拉顯示：** `name` + `（` + `englishName` + `）`。

# 四、API 規劃

既有分類、議題、TODO、專案路徑維持，下列為新增或增量。

### 4.1 公司成員

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 列表 | GET | `/company-members?q=` | `q` 可省略；比對 name／englishName | `CompanyMember[]` | — |
| 新增 | POST | `/company-members` | `CompanyMemberWrite` | `CompanyMember` | 400 |
| 更新 | PUT | `/company-members/{id}` | `CompanyMemberWrite` | `CompanyMember` | 404；400 |
| 刪除 | DELETE | `/company-members/{id}` | 無 | `{ deleted: true }` | 404；409 使用中 |

`CompanyMemberWrite`：`name`（必填、最長 50）、`englishName`（必填、最長 50）、`remark`（可空字串、最長 400）

`CompanyMember`：`id`, `name`, `englishName`, `remark`, `createdAt`, `updatedAt`

排序：`name` 再 `id`。名稱不唯一。

### 4.2 客戶公司

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 列表 | GET | `/client-companies?q=` | `q` 可省略；比對公司名（詳情列表另含窗口名過濾見 4.3） | 下拉用：`ClientCompanyListItem[]`。維護頁用 4.3 樹 | — |
| 新增 | POST | `/client-companies` | `{ name }` | `ClientCompany` | 400；409 名稱重複 |
| 更新 | PUT | `/client-companies/{id}` | `{ name }` | `ClientCompany` | 404；400；409 |
| 刪除 | DELETE | `/client-companies/{id}` | 無 | `{ deleted: true }` | 404；409 使用中 |

`name` 必填、最長 100、全系統唯一（忽略大小寫）。

`ClientCompanyListItem`：`id`, `name`（供下拉，宜輕量）

`ClientCompany`：`id`, `name`, `createdAt`, `updatedAt`

維護頁建議一次 `GET /client-companies/tree?q=` 回傳公司＋窗口＋聯絡，避免 N+1。`q` 有值時留下公司名稱或任一窗口名稱命中的公司（含其全部窗口）。

### 4.3 窗口與聯絡

路徑 `{companyId}` 必須為所屬公司，否則 404。

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 樹 | GET | `/client-companies/tree?q=` | 見上 | `ClientCompanyTree[]` | — |
| 新增窗口 | POST | `/client-companies/{companyId}/contacts` | `ClientContactWrite` | 該公司完整窗口列表（含聯絡） | 404；400；409 窗口名重複 |
| 更新窗口 | PUT | `/client-companies/{companyId}/contacts/{id}` | `ClientContactWrite` | 同上 | 404；400；409 |
| 刪窗口 | DELETE | `/client-companies/{companyId}/contacts/{id}` | 無 | 同上 | 404 |
| 新增加聯絡 | POST | `/client-companies/{companyId}/contacts/{id}/channels` | `ContactChannelWrite` | 該窗口完整 `channels` | 404；400 |
| 改聯絡 | PUT | `.../channels/{channelId}` | `ContactChannelWrite` | 該窗口完整 `channels` | 404；400 |
| 刪聯絡 | DELETE | `.../channels/{channelId}` | 無 | 該窗口完整 `channels` | 404 |

`ClientContactWrite`：`name`（必填、最長 50）、`title`（職位，可空字串、最長 50）

`ContactChannelWrite`：`type`（`phone`／`mobile`／`email`／`teams`／`other`）、`value`（必填、最長 200）

`ClientCompanyTree`：`id`, `name`, `contacts: ClientContact[]`

`ClientContact`：`id`, `clientCompanyId`, `name`, `title`, `channels: ContactChannel[]`, `createdAt`, `updatedAt`

`ContactChannel`：`id`, `type`, `value`

同一公司窗口名唯一（忽略大小寫）。不可改掛公司。

### 4.4 專案增量

`ProjectWrite` 加：`clientCompanyId`（必填）、`ownerMemberId`（可 null）。

`ProjectListItem`／`ProjectDetail` 加：`clientCompanyId`, `clientCompanyName`, `ownerMemberId`, `ownerMemberName`, `ownerMemberEnglishName`。舊列無廠商時 id／name 為 null。

寫入：`clientCompanyId` 缺或公司不存在 → 400。`ownerMemberId` 有值但成員不存在 → 400。

`DELETE /client-companies/{id}` 的 409 message：`使用中，共 {n} 筆專案、{n} 筆正式議題`（只列＞0）。

`DELETE /company-members/{id}`：`使用中，共 {n} 筆專案`

### 4.5 正式議題增量

`IssueWrite` 加 `clientCompanyId`（必填）。`IssueDto` 加 `clientCompanyId`, `clientCompanyName`。寫入規則同專案廠商。

### 4.6 專案議題增量

`ProjectIssue`（讀）加 `clientCompanyId`, `clientCompanyName`（來自專案）。`ProjectIssueWrite` **不含**這兩欄，後端忽略若誤傳。

## 7.2 實體關聯概覽

- clientCompany 1:N clientContact 1:N contactChannel
- clientCompany 1:N project、1:N issue（寫入後應有值）
- companyMember 1:N project（owner，可空）
- 刪 clientCompany → 窗口與聯絡消失；若仍有 project／issue 引用則不可刪
- 刪 companyMember → 若有 project.ownerMemberId 則不可刪
- projectIssue 不指向 clientCompany

## 7.3 資料流向

成員頁 → 公司成員／公司樹。  
快捷新增或成員頁 → 客戶公司 → 專案／議題下拉。  
儲存專案／議題 → 必帶 clientCompanyId。  
刪除 → COUNT 引用。

## 7.4 DA 接手指引

有 Database 持久化。第四階段目錄新開《資料庫設計書》增量；不覆寫第一、三階段設計書本文。

- 主鍵 BIGINT AUTO_INCREMENT、snake_case、C# PascalCase。
- 新表：公司成員、客戶公司、客戶窗口、窗口聯絡。
- 既有 `project`、`issue` **加欄** `client_company_id`（可 NULL 以容舊列）、`project` 另加 `owner_member_id`（可 NULL）。
- 應用層寫入把廠商當必填；不要把舊列一次 UPDATE 成假廠商。
- 刪公司 CASCADE 窗口與聯絡；刪窗口 CASCADE 聯絡。
- 刪公司／成員對 project／issue 用 RESTRICT，應用層先 COUNT。
- `client_company.name` 唯一；`(client_company_id, contact name)` 唯一。
- 不建成員帳號、不建匯入表、不建追蹤／預約表。
- 種子：不預設公司或成員。
- 舊庫 `EnsureSchema` 必須能 ALTER 加欄、CREATE 新表。

# 十、系統限制

- 單人、無登入
- 舊專案／舊議題未補廠商前仍能看、不能存
- 專案議題不選廠商、不選處理人
- 刪除不可復原
- 聯絡類型固定五種

# 十一、開發注意事項

- 下拉 key 用 id，不要用名稱（成員可同名）。
- 議題列表／詳情與新增頁都要加廠商，避免只改一頁。
- 單元測試至少：公司名忽略大小寫唯一；同公司窗口名唯一、跨公司可同名；成員同中文名可兩筆；快捷新增回 id；專案／議題無廠商 400；有廠商可存；舊列 GET 廠商 null；刪被引用公司／成員 409；刪公司後窗口不在；專案議題 write 不存自己的廠商。
- 前端必填星號與儲存前檢查，後端仍驗證。

# 十二、已確認決策

- 架構沿用，不換框架。
- 維護頁 `/members`，API 分 `/company-members` 與 `/client-companies`。
- 窗口路徑用 `contacts`（客戶窗口），聯絡用 `channels`，避免與公司成員混淆。
- 巢狀編輯：單一 wide dialog＋列表，見 Spike。
- 不調整產品範圍（無追蹤、無預約、無 Excel）。
