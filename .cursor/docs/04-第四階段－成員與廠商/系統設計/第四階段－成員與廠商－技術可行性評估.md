# 第四階段－成員與廠商－技術可行性評估

**角色：** RD（Tech Spike，非正式開發）  
**日期：** 2026-09-03  
**依據：** 規格書 §8.1 待評估項、系統設計草擬 API／UI

## 結論

**可行。** 沿用既有 React SPA、ASP.NET Core 9、MySQL、粉彩 token 與 `AppSelect`／`AppDialog`。不必新元件庫。舊專案／議題廠商欄可 NULL，寫入再必填，與現有 EnsureSchema 加欄方式相同。

本輪無須於 Spike 交付正式功能程式。

## 評估項目

| 項目 | 結果 | 說明 |
|------|------|------|
| 雙 tab 維護頁 | 可行 | 新路由 `/members`；狀態用 search 或本地 tab。關鍵字 debounce 後打 `q=`。 |
| 公司＋窗口＋聯絡編輯擁擠 | 可行 | 公司 dialog 只編名稱。窗口 `wide` dialog：上方名稱／職位，下方聯絡列（類型 `AppSelect`＋內容＋刪）。不加第三方面板。 |
| 廠商必填與舊資料 | 可行 | 欄位可 NULL；前端有值才送；後端 Create／Update 驗證。列表照常顯示。 |
| 快捷新增 | 可行 | 小 dialog → `POST /client-companies` → set 表單 id。 |
| 同名成員 | 可行 | option 顯示 `name（englishName）`，value 為 id。 |
| 刪除 COUNT | 可行 | 與分類刪除同一模式。 |
| 專案議題跟廠商 | 可行 | DTO 從 project join 帶出；Write 不含該欄。 |
