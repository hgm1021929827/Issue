# 第十階段－正式議題獨立列表頁－功能規格書

**角色：** PM  
**版本：** v1.0  
**日期：** 2026-09-04  
**需求類型：** ① Web 應用（UI only，無 Database）  
**來源：** 使用者「我想將議題列表單獨一頁，項專案那樣」

已跳過討論文件（F-01）。假設：正式議題清單從首頁拆出，版面與導覽對齊 `/projects`；首頁保留追蹤項目與行事曆；排入預計項目改在首頁以選單選擇議題後點月曆。API 與 Schema 不改。

### PV-F01

| 項目 | 需求 |
|------|------|
| 目的 | 議題列表獨立一頁，操作方式與專案列表相同 |
| 優先級 | Must |
| MVP | 是 |
| 流程 | 導覽「議題」進入 `/issues`。標題「議題」、分類 Chip、「新增議題」。列點進 `/issues/:id`。頂欄不再放「新增議題」。 |
| 限制 | 不改議題欄位與寫入規則。不把完整清單留在首頁。 |
| 驗收 | `/issues` 有清單；首頁無完整議題列表；仍可從首頁排入預計項目。 |

### PV-F02

| 項目 | 需求 |
|------|------|
| 目的 | 首頁專心顯示追蹤與月曆 |
| 優先級 | Must |
| MVP | 是 |
| 流程 | 首頁：需要追蹤項目 → 排入預計項目下拉 → 月曆。刪除議題後回 `/issues`。 |
| 限制 | 月曆視角、跳轉、移除預計項目維持既有行為。 |
| 驗收 | 首頁看不到完整議題清單；選議題後可點月曆排入。 |

**本功能無 Database 持久化，第七章 Database 項目 N/A。**
