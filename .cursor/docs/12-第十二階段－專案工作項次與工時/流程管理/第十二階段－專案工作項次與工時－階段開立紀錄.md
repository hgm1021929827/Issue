## 二、範圍凍結

| 本階段做 | 本階段不做（留給之後新階段） |
|----------|------------------------------|
| 專案工作項次（與專案議題平行、互不從屬） | 正式議題匯入（`議題匯入範本.xls`／UOF HTML） |
| 工時紀錄（項次／議題各自；同日最多一筆；不算專案總工時） | 專案檔內其他工作表（查核點、CheckList、議題圖、工作項目(給)、表單進度等） |
| 專案 Excel 匯入與再次匯入（只讀「工作項目」「議題單」） | 加簽狀態保存與恢復、加簽大分類 |
| 匯入差異（未找到不得自動刪；保留明顯標示或刪除；識別變更＝舊未找到＋新新增） | 預約連線 CRUD／清單／行事曆 |
| 備註工時比對（只逐日比對，不自動新增／覆蓋網頁工時） | 臨時工作、登入／權限 |

欄位細節、畫面承載、匯入篩選與「管理欄位」清單：交 PM《規格書討論文件》勾選，WFM 不定案。

已知約束（前階段已確認、本輪不得推翻為登入系統）：

- 第一階段 Q3＝A：單人、無登入；成員與客戶是**通訊錄資料**，不是帳號。
- 第四階段：公司成員與客戶窗口兩套主檔；專案廠商必填、專案可選負責人員。
- 第七、八階段：專案詳情已有「專案內容／專案議題」tab，議題為左右切分。
- 補充文件與舊 Excel 原稿衝突時，以補充文件為準；舊稿見 [歷史資料說明](../../04-第四階段－成員與廠商/歷史資料/說明.md)，**不得直接實作**。
- 專案實檔對照：[P-20260108-1497 104-中華資安-UOFX客製.xlsx](../../../../Template/P-20260108-1497 104-中華資安-UOFX客製.xlsx)、[P-20260522-1553 巴黎人壽-eFlow-IFRS17會計科目調整Phase2.xlsx](../../../../Template/P-20260522-1553 巴黎人壽-eFlow-IFRS17會計科目調整Phase2.xlsx)。只當表頭／備註寫法參考，不是現行規格。

已知缺口（PM 必須先討論，不可因總覽有標題就跳過）：

- 無登入時，「目前使用者」匯入篩選如何指定
- 工作代號是否必填（補充：唯一鍵＝專案編號＋工作代號；舊稿允許空代號）
- 工作代號階層寫法（實檔 `2.2.1`）只當字串唯一鍵，或要在畫面呈現層級（補充文件說無階層／父子／排序意義）
- 工時是否含專案本體（補充：不算專案總工時；舊稿專案本體也有逐日工時）
- 實際起迄是否仍要「標記完成」（舊稿有；補充只說由工時推導）
- Excel「管理欄位」清單：哪些網頁不可改
- 未找到列：保留／刪除的操作時機與畫面
- 專案頁承載（是否第三 tab、是否左右切分）、首頁／行事曆是否列項次
- 工作項次要不要掛追蹤 TODO
- 負責人員：成員下拉 vs Excel 文字（實檔可多人／All／客戶名）
- 處理時間(PM/SA/PG/QC) 欄是否忽略，只解析備註逐日工時
- 專案檔名／檔內代號與既有 `project_code` 如何對上
