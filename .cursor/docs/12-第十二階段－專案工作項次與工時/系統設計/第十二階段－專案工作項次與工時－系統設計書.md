# 三、功能流程

### 3.1 匯入

1. 使用者在專案清單或已存專案詳情開 dialog：一個檔＋目前使用者（成員 id，預設 localStorage）。
2. `POST /project-imports/resolve-project`（只帶檔）：解析檔名。無代號 → 400。有代號且專案存在 → `{ status: "ready", projectId, projectCode }`。有代號但無專案 → `{ status: "needProject", projectCode, suggestedName }`。此步**不寫入**項次／議題。
3. `needProject`：`navigate('/projects/new', { state: { importFile, currentUserMemberId, projectCode, suggestedName } })`。表單預填代號／名稱。取消或失敗：不匯入。`POST /projects` 成功後，用 state 裡的同一 `File` 打 `POST /projects/{id}/imports`。
4. `ready`：直接 `POST /projects/{projectId}/imports`（檔＋`currentUserMemberId`）。不比對「目前開的詳情 id」；只信檔名對到的專案。
5. 匯入服務（單一交易）：驗兩張表；篩選列；工作項次／議題 upsert；備註可解析且網頁缺該日則寫入工時（不覆蓋、不刪已有）；組剩餘工時差異與未找到清單；提交。
6. 前端進 `/projects/{id}/import-result`（state 帶 `ImportResult`）。使用者對每筆未找到選 keep／delete 後 `POST /projects/{id}/import-decisions`。keep → `missingKept=true`；delete → 刪實體（含工時、追蹤）。未送決策就離開：upsert 已生效，未找到列維持原 `missingKept`。
7. 同一識別再出現在後來的匯入：`missingKept=false`，並更新管理欄位。

檔名：去副檔名後，第一個空白前＝`projectCode`（忽略大小寫對 `project.projectCode`）；其餘＝建議名稱。

工作項目有效列：通過篩選且工作代號 trim 非空。議題單有效列：通過篩選且項次 trim 非空。工作項目有效列為 0 → 400 整批不寫。

篩選：儲存格 trim 後忽略大小寫等於 `all`，或包含目前使用者**中文名或英文名**（英文名空白則只比中文名）。

工作項次鍵：同一專案 `workItemCode` 忽略大小寫。空白代號：列異常。同檔撞鍵：後列異常。不讀「項次」與處理時間四欄。

議題鍵：同一專案 `seqNo` 忽略大小寫。新增列分類預設同第三階段。

備註工時：可解析且網頁缺該日則寫入，已有該日只比對；見 §3.3。Excel 日期序號當日期。

### 3.2 工時與完成

- 實際開始：每次該主體工時變更後＝最早 `workDate`；無工時＝null。
- 標記完成：`isCompleted=true`；有工時則 `actualEndDate`＝最晚 `workDate`，無工時則 null。
- 取消完成：`isCompleted=false`，`actualEndDate=null`；不刪工時、不改實際開始。
- 已完成後再加工時：不改 `actualEndDate`。

### 3.3 備註解析

每行獨立。建議語意：

```
可選西元年/或- 月/或- 日 ，空白，可選 - ，空白，正數（可小數），H 或 h
```

對不上 → `unparseableRemark`。年省略＝伺服器當地年。可解析且網頁無該日 → 新增工時並重算實際開始。已有該日不覆蓋。比對剩餘差異：同日小時不同、網頁有 Excel 無、無法解析。

### 3.4 跳轉

- 項次：`/projects/{projectId}?workItem={id}`
- 項次＋追蹤：`/projects/{projectId}?workItem={id}&trackTodo={id}`
- 月曆 `source=workItem` 同上。

# 四、API 規劃

既有分類、議題、專案、專案議題、追蹤路徑維持。下列新增或增量。

`workType` 增量：`workItem`（首頁追蹤、月曆）。

### 4.1 工作項次

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 列表 | GET | `/projects/{projectId}/work-items` | 無 | `WorkItem[]` | 404 |
| 單筆 | GET | `/projects/{projectId}/work-items/{id}` | 無 | `WorkItem` | 404 |
| 標記完成 | PUT | `/projects/{projectId}/work-items/{id}/complete` | `{ isCompleted }` | `WorkItem` | 404 |
| 刪除 | DELETE | `/projects/{projectId}/work-items/{id}` | 無 | `{ deleted: true }` | 404 |

無 POST／無一般 PUT（管理欄位唯讀）。

`WorkItem`：`id`, `projectId`, `workItemCode`, `title`（工作說明）, `plannedDays`, `ownerName`, `startDate`, `dueDate`, `isCompleted`, `actualStartDate`, `actualEndDate`, `missingKept`, `remark`, `hoursTotal`, `createdAt`, `updatedAt`

`hoursTotal`＝該筆工時加總（讀取計算）。列表排序：`workItemCode` 字串再 `id`，不解析階層。

### 4.2 工時

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 項次工時列表 | GET | `/projects/{projectId}/work-items/{id}/hours` | 無 | `WorkHour[]` | 404 |
| 項次工時新增 | POST | 同上 | `WorkHourWrite` | 該主體完整工時列表＋重算後的主體摘要可選 | 404；400；409 同日 |
| 項次工時更新 | PUT | `/projects/{projectId}/work-items/{id}/hours/{hourId}` | `WorkHourWrite` | 完整列表 | 404；400；409 |
| 項次工時刪除 | DELETE | 同上 hour 路徑 | 無 | 完整列表 | 404 |
| 議題工時 | GET／POST／PUT／DELETE | `/projects/{projectId}/items/{itemId}/hours`（與 hourId） | 同左 | 同左 | 同左 |

`WorkHourWrite`：`date`（必填）、`hours`（必填、＞0、最多兩位小數、上限 999.99）、`remark`（可空、最長 2000）。

`WorkHour`：`id`, `date`, `hours`, `remark`

寫入成功後重算該主體 `actualStartDate`。

### 4.3 專案議題增量

`ProjectIssue`／`ProjectIssueWrite` 加：`handlerName`（可空字串、最長 50）、`isCompleted`、`actualStartDate`、`actualEndDate`、`missingKept`（讀取）、`remark`。`hoursTotal` 可選。

`PUT /projects/{id}/work-items/{id}/remark`、`PUT /projects/{id}/items/{id}/remark`：`{ remark }`，最長 2000。匯入勾選「保留進項次備註最後一行」寫入此欄，不寫工時備註。

`PUT` 已存議題：若 request `seqNo` 與庫存不同 → 400 `項次建立後不可修改`。新增仍要 `seqNo`。

`PUT .../items/{id}/complete`：`{ isCompleted }`，規則同工作項次。

### 4.4 追蹤增量

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 項次下追蹤列表 | GET | `/projects/{projectId}/work-items/{id}/track-todos` | 無 | `TrackTodo[]` | 404 |
| 項次下新增 | POST | 同上 | `TrackTodoWrite` | 該項次完整列表 | 404；400 |

`TrackTodo.workType` 可為 `workItem`；`workId`＝工作項次 id；`projectId` 供跳轉。

`GET /track-todos` 的 `workLabel`：工作項次＝`工作代號 工作說明`（可加專案代號）。

跳轉：`workItem` → `/projects/{projectId}?workItem={workId}&trackTodo={id}`

改專案廠商：COUNT 再含該專案工作項次上 `clientContact` 追蹤。

刪成員／窗口：COUNT 含項次追蹤。

### 4.5 匯入

| 名稱 | 方法 | 路徑 | Request | Response data | Error |
|------|------|------|---------|---------------|-------|
| 解析檔名對專案 | POST | `/project-imports/resolve-project` | multipart `file` | `ResolveProject` | 400 非 xlsx／無代號 |
| 匯入寫入 | POST | `/projects/{projectId}/imports` | multipart `file`＋`currentUserMemberId` | `ImportResult` | 404；400 缺表／零有效列／非 xlsx／成員不存在 |
| 未找到決策 | POST | `/projects/{projectId}/import-decisions` | `ImportDecisionRequest` | `{ applied: true }` | 404；400 未選完或 id 不屬該專案 |

`ResolveProject`：`status`＝`ready`｜`needProject`；`projectId`（ready 才有）；`projectCode`；`suggestedName`（可空）。

`ImportResult`：`projectId`, `summary`（`workItemCreated`, `workItemUpdated`, `workItemSkipped`, `issueCreated`, `issueUpdated`, `issueSkipped`）, `rowErrors[]`, `hourDiffs[]`, `hourReviews[]`, `notFound[]`

`rowErrors`：`sheet`, `rowIndex`, `kind`（`missingWorkItemCode`／`duplicateWorkItemCode`／`missingSeqNo`／…）, `message`

`hourDiffs`：`ownerKind`（`workItem`｜`projectIssue`）, `ownerId`, `ownerLabel`, `kind`（`hoursWebOnly`／`hoursExcelOnly`／`hoursDiffer`／`unparseableRemark`）, `date`（可空）, `excelHours`, `webHours`, `detail`（無法解析時為該些列原文）, `remark`（Excel 備註原文）

`hourReviews`：備註需逐行處理時（有尚未套用的文字列或剩餘工時差異）。`lines[]` 依儲存格原順序：`index`, `text`, `kind`（`hour`｜`text`）, `date`, `hours`。Excel 文字列若已完整出現在該項次／議題備註，不列入；僅剩已處理文字且無工時差異則不產生該筆。畫面：工時列顯示日期／小時；文字列用文字框，可勾選保留進項次／議題備註最後一行；每列可刪。確認附加備註為冪等。

`notFound`：`ownerKind`, `ownerId`, `ownerLabel`（項次＝代號＋說明；議題＝項次＋標題）

`ImportDecisionRequest`：`decisions: { ownerKind, ownerId, action: keep｜delete }[]`  
必須**恰好覆蓋**本次結果裡的 `notFound` 每一筆（前端帶齊）。缺漏 → 400。

400 文案（繁中）：`請選擇一個 Excel 檔`、`僅支援 xlsx`、`檔名解析不出專案代號`、`找不到工作表「工作項目」`、`找不到工作表「議題單」`、`沒有符合目前使用者的工作項次`、`請先選擇目前使用者`、`請為每筆未找到資料選擇保留或刪除`。

### 4.6 行事曆與專案刪除增量

`GET` 既有月曆：到期日視角加有 `dueDate` 的工作項次；`source=workItem`；`projectId`＋`id`。

`DELETE /projects/{id}` 回傳加 `workItemCount`。前端確認文案列出。連刪項次、工時、項次追蹤。

刪大／小分類：既有 message 加「工作項次 {n} 筆」（只列＞0）。

`GET /projects` 列表項可選帶 `workItemCount`（首頁要用再另 GET 列表即可，不必改清單契約）。

## 7.2 實體關聯概覽

- 一個 project 有 0..N 個 workItem 與 0..N 個 projectIssue；兩者互不從屬。
- 一個 workItem 有 0..N 個 workHour、0..N 個 trackTodo。
- 一個 projectIssue 有 0..N 個 workHour（另有既有 trackTodo）。
- 刪 project → 刪其 workItem、projectIssue 及底下工時與追蹤。
- 刪 workItem／projectIssue → 刪其 workHour 與追蹤。
- workHour 不掛在 project 本體。

## 7.3 資料流向

瀏覽器選檔 → resolve-project（可只讀檔名，必要時開檔確認是 xlsx）→ 或新增專案 → imports（ClosedXML → 篩選 → 交易 upsert → 比對工時）→ 結果 state → import-decisions。工時 CRUD 只走 hours API。月曆／首頁讀 workItem.dueDate。

## 7.4 DA 接手指引

有 Database 持久化。須新表（或等價）對應 workItem、workHour；project_issue 加增量欄；track_todo 能指向 workItem。刪專案／項次／議題須能連刪工時與追蹤。unique：同專案 workItemCode；同歸屬同日 workHour。§三每個新表須有七欄欄位設計表。localStorage 偏好 N/A，不要建表。

# 八、權限流程

單人無登入。`currentUserMemberId` 只是篩選參數，不是身分驗證。

# 十、系統限制

- 不手新增工作項次；不改管理欄位。
- 不匯其他工作表、不匯正式議題、不匯 .xls。
- 不一次多檔、不建匯入歷程表、不伺服器暫存檔。
- 不算專案總工時；專案本體無逐日工時。
- 不依工作代號建樹。
- 項次無一般 TODO 樹。
- 月曆不上預計項目拖項次。
