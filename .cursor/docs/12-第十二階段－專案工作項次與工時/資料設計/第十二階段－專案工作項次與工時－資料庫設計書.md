## 一、資料庫設計理念

個人單人系統。工作項次獨立成表，與 `project_issue` 平行掛 `project`。工時「恰好一種歸屬」用兩個可空 FK，以便 CASCADE。追蹤第四承載同樣加一個可空 FK，並把既有「三選一」改成「四選一」。

主鍵 `BIGINT AUTO_INCREMENT`。表名與欄位 `snake_case`。庫名 `issue_tracker`，`utf8mb4`。

不建匯入歷程表。`hours_total` 查詢計算，不存欄。`importMemberPref` 在本機，不建表。

## 三、Table 詳細設計

### project_work_item

中文名稱：工作項次

用途：隸屬一筆專案的工作包。唯一鍵為同專案工作代號。管理欄只由匯入寫入。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| project_work_item_id | 編號 | BIGINT | PRIMARY KEY | 否 | AUTO_INCREMENT | 主鍵 |
| project_id | 所屬專案 | BIGINT | NOT NULL；FK | 否 | — | 指向 project；刪專案 CASCADE |
| work_item_code | 工作代號 | VARCHAR(50) | NOT NULL；同專案 UNIQUE | 否 | — | 對應 `workItemCode`；勿存空字串 |
| title | 工作說明 | VARCHAR(4000) | NOT NULL | 否 | `''` | 對應 `title` |
| planned_days | 計畫人天 | DECIMAL(8,2) | ≥0 | 是 | NULL | 對應 `plannedDays` |
| owner_name | 負責人員 | VARCHAR(200) | NOT NULL | 否 | `''` | Excel 原文 |
| start_date | 預計開始日 | DATE | — | 是 | NULL | — |
| due_date | 預計完成日 | DATE | — | 是 | NULL | 行事曆到期日 |
| is_completed | 是否完成 | TINYINT(1) | NOT NULL | 否 | `0` | — |
| actual_start_date | 實際開始日 | DATE | — | 是 | NULL | 應用層依工時重算 |
| actual_end_date | 實際結束日 | DATE | — | 是 | NULL | 標記完成時可空 |
| missing_kept | 本次未找到保留 | TINYINT(1) | NOT NULL | 否 | `0` | 對應 `missingKept` |
| remark | 備註 | VARCHAR(2000) | NOT NULL | 否 | `''` | 匯入勾選保留的文字列 |
| created_at | 建立時間 | DATETIME | NOT NULL | 否 | CURRENT_TIMESTAMP | — |
| updated_at | 更新時間 | DATETIME | NOT NULL | 否 | CURRENT_TIMESTAMP | 更新時刷新 |

C#：`ProjectWorkItem`；`ProjectWorkItemId`、`ProjectId`、`WorkItemCode`、`Title`、`PlannedDays`、`OwnerName`、`StartDate`、`DueDate`、`IsCompleted`、`ActualStartDate`、`ActualEndDate`、`MissingKept`、`CreatedAt`、`UpdatedAt`。

JSON `id`＝`project_work_item_id`。同專案代號唯一依預設 ci collation；應用層仍 trim、拒絕空白。

### work_hour

中文名稱：工時紀錄

用途：某一日的小時。恰好歸屬工作項次或專案議題之一。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| work_hour_id | 編號 | BIGINT | PRIMARY KEY | 否 | AUTO_INCREMENT | 主鍵 |
| project_work_item_id | 工作項次歸屬 | BIGINT | FK | 是 | NULL | 與 project_issue_id 恰好一個有值 |
| project_issue_id | 專案議題歸屬 | BIGINT | FK | 是 | NULL | — |
| work_date | 日期 | DATE | NOT NULL | 否 | — | 對應 `date` |
| hour_value | 工時 | DECIMAL(6,2) | NOT NULL；＞0 且 ≤999.99 | 否 | — | 對應 JSON `hours` |
| remark | 備註 | VARCHAR(2000) | NOT NULL | 否 | `''` | 網頁工時備註 |

C#：`WorkHour`；`WorkHourId`、`ProjectWorkItemId`、`ProjectIssueId`、`WorkDate`、`HourValue`、`Remark`。

JSON 不輸出兩個 FK；由 API 路徑決定歸屬。

CHECK：`(project_work_item_id IS NOT NULL) + (project_issue_id IS NOT NULL) = 1`。

### project_issue（加欄）

中文名稱：專案議題

用途：第三階段專案議題。本輪加處理人、完成、實際起迄、未找到標示。既有欄不重出。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| handler_name | 處理人員 | VARCHAR(50) | NOT NULL | 否 | `''` | 對應 `handlerName` |
| is_completed | 是否完成 | TINYINT(1) | NOT NULL | 否 | `0` | — |
| actual_start_date | 實際開始日 | DATE | — | 是 | NULL | 依該議題工時 |
| actual_end_date | 實際結束日 | DATE | — | 是 | NULL | 標記完成時可空 |
| missing_kept | 本次未找到保留 | TINYINT(1) | NOT NULL | 否 | `0` | — |
| remark | 備註 | VARCHAR(2000) | NOT NULL | 否 | `''` | 匯入勾選保留的文字列 |

C# `ProjectIssue` 加：`HandlerName`、`IsCompleted`、`ActualStartDate`、`ActualEndDate`、`MissingKept`、`Remark`。

舊列加欄後視同未完成、無實際日、未標示保留。`seq_no` 不可改由應用層執行，欄位定義不變。

### track_todo（加欄）

中文名稱：追蹤 TODO

用途：第五階段追蹤。本輪可掛工作項次。既有欄不重出。

#### 欄位設計

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| project_work_item_id | 所屬工作項次 | BIGINT | FK | 是 | NULL | 與 issue_id、project_id、project_issue_id 四者恰好一個有值 |

C# `TrackTodo` 加：`ProjectWorkItemId`。EnsureSchema 將工作 CHECK 改為四選一。

## 四、Table 關聯

- `project_work_item.project_id` → `project.project_id` ON DELETE CASCADE
- `work_hour.project_work_item_id` → `project_work_item.project_work_item_id` ON DELETE CASCADE
- `work_hour.project_issue_id` → `project_issue.project_issue_id` ON DELETE CASCADE
- `track_todo.project_work_item_id` → `project_work_item.project_work_item_id` ON DELETE CASCADE
- 工作項次不建分類 FK（規格無項次分類）

刪專案：CASCADE 刪 `project_work_item` → 其 `work_hour` 與 `track_todo`。既有 `project_issue` CASCADE 不變。

---

## 五、Index 建議

- UNIQUE (`project_id`, `work_item_code`) on `project_work_item`
- INDEX (`project_id`, `due_date`) on `project_work_item`（月曆）
- UNIQUE (`project_work_item_id`, `work_date`) on `work_hour`（NULL 端不互撞）
- UNIQUE (`project_issue_id`, `work_date`) on `work_hour`
- INDEX (`project_work_item_id`, `sort_order`) on `track_todo`

---

## 六、Constraint

- 工作項次代號：UNIQUE＋應用層 trim、空白拒收。
- 工時：`hour_value`＞0；恰好一個歸屬 FK：CHECK＋應用層；同日 409。
- 起迄順序、項次鎖定：僅應用層。
- 追蹤四選一 CHECK＋應用層。
- 成員／窗口刪除仍 RESTRICT；COUNT 含項次追蹤。

---

## 七、資料生命週期

- 工作項次只由匯入新增；詳情或結果頁可刪；刪專案全刪。
- 工時隨主體增刪改；刪主體 CASCADE。
- `missing_kept` 由匯入決策／再次出現改寫。
- 無種子。

## 八、命名規範

對齊 AGENTS.md：`snake_case` 表欄、BIGINT 主鍵、C# PascalCase。JSON camelCase。`hour_value` 對 JSON `hours`；`work_date` 對 `date`。

## 九、設計決策

| 決策 | 原因 |
|------|------|
| 工時兩 FK 不用 kind+id | 與第五階段追蹤相同，才能真 CASCADE |
| 追蹤加第四 FK 不拆表 | 沿用一張 track_todo |
| 不建匯入批次表 | Spike／SA：結果走前端 state |
| 項次無分類欄 | 規格管理欄不含分類 |
| planned_days 可 NULL | 規格可空 |
