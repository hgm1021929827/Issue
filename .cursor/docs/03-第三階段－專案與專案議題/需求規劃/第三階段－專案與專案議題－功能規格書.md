# 一、專案介紹

本階段在既有個人工作追蹤上，新增**專案**與**專案議題**兩種獨立工作資料，讓使用者能手動建檔、維護與從行事曆看到預計完成日。

專案議題不是第一階段的「正式議題」，也不把正式議題掛到專案底下。Excel 匯入、廠商、工時、臨時工作、專案下 TODO 不在本輪。

# 二、專案目標

1. 可新增、編輯、刪除專案；畫面以使用者輸入的**專案代號**識別，全系統唯一。
2. 一筆專案底下可維護多筆**專案議題**；同一專案內**項次**唯一。
3. 專案與專案議題沿用現有大小分類；清單與行事曆顏色以**小分類**為準；進度或完成靠改小分類，無獨立核取、不靠改大分類。
4. 導覽提供獨立專案清單與詳情；有預計完成日者出現在首頁既有行事曆的**到期日**視角。
5. 刪專案須確認，確認後連同其專案議題一併刪除。刪分類時須檢查是否被專案或專案議題使用。

# 三、產品定位

| 欄位 | 說明 |
|------|------|
| **需求類型** | ① Web 應用功能（含 UI／API，需 Database） |
| **本期範圍** | 專案 CRUD 與清單／詳情；專案議題 CRUD（隸屬專案）；共用大小分類與刪除擴大檢查；行事曆到期日視角加上專案／專案議題預計完成日 |
| **不在範圍** | Excel 匯入、工作表規則、負責人員／處理人篩選、日期工時、Excel 備註工時比對、匯入異常；臨時工作；廠商／客戶公司／快捷新增；計畫人天、工作代號、實際起迄、工時累計；專案或專案議題的 TODO；正式議題綁專案；需要追蹤的 TODO；加簽恢復；預約連線；行事曆「預計項目」拖專案；回收筒；登入。本輪**有** Database、API、程式實作。 |

新畫面與元件必須對齊第二階段《視覺設計規格書》（奶油白底、霧藍主色、棕灰文字、大圓角淺陰影；重用 `frontend/src/styles.css` 的 `:root` token）。確認與危險操作用 HTML `dialog`；錯誤用頁內橫幅，不用 `alert`／`prompt`／`confirm`。

前後端切分由 SA／Tech Spike 定案，本規格不鎖死元件庫。

### PJ-F03：專案議題 CRUD

| 項目 | 需求 |
|------|------|
| 功能目的 | 維護隸屬某專案的議題列；唯一語意為專案＋項次 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 在專案詳情新增：項次（必填）、標題（必填）、內容（可空）、大分類（必選，預設規則同 PJ-F01）、小分類（可空）、預計開始日（可空）、預計完成日（可空）。可編輯同一組欄位。可刪除該筆（確認後刪，不影響其他列）。 |
| 功能限制 | 項次在**同一專案內**不可重複（忽略大小寫）；不同專案可以有相同項次。無全系統另一套專案議題編號。無處理人、工時、實際起迄。本輪不可把專案議題搬到別的專案。 |

### PJ-F04：共用分類與刪除擴大檢查

| 項目 | 需求 |
|------|------|
| 功能目的 | 專案與專案議題使用現有大小分類；刪分類時一併保護被引用資料 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 分類仍只在「分類設定」維護。專案／專案議題表單的大、小分類下拉與正式議題相同（含空白小分類選項顯示目前大分類名稱）。刪大分類或小分類前，除檢查正式議題外，須檢查是否被**專案**或**專案議題**使用（含目前選到的小分類）。使用中不可刪，提示須含使用筆數（可分正式議題／專案／專案議題，或合計但訊息須讓人知道與專案有關）。 |
| 功能限制 | 不另做專案專用分類或色票。不在本輪改變分類設定的新增／改名規則。 |
| 注意事項 | 工作資料必須保存小分類識別；空白＝空值。此為對既有刪除檢查的**增量**，不改第一階段文件本文。 |
| 驗收條件 | 專案與專案議題可選現有分類並持久化；空白小分類不寫入小分類資料；刪除仍被專案或專案議題使用的小分類／大分類失敗並提示筆數；僅被正式議題使用時行為與第一階段相同並加上專案側為零的情況仍可刪（若無專案引用）。 |

### PJ-F05：狀態以小分類表達

| 項目 | 需求 |
|------|------|
| 功能目的 | 進度或完成靠改小分類；不做獨立完成核取，也不靠改大分類標記完成 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 使用者在專案或專案議題表單選擇小分類。若要表達「已完成」或某進度，須先在分類設定於所屬大分類下建立對應小分類，再選取。大分類仍必選，用於分組與篩選，但改大分類不是完成操作。 |
| 功能限制 | 無「是否完成」核取方塊。系統不把任何小分類名稱寫死為完成，不因到期日或專案議題全部如何而自動改分類。 |
| 注意事項 | 清單、詳情、行事曆標記的顏色與狀態文字以小分類為準（空白則大分類名稱＋備選色 `#8FA8C8`）。 |
| 驗收條件 | 畫面沒有專案／專案議題完成核取；改小分類後清單與行事曆色標與文字更新；只改大分類而不改小分類時，若小分類已空或不屬新大分類則依 PJ-F01 重設規則，不得出現獨立完成旗標。 |

| 項目 | 需求 |
|------|------|
| 功能目的 | 整包移除專案及其議題列，避免留下無主專案議題 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 在清單或詳情點刪除。以 `dialog` 確認，須顯示專案代號（或名稱）以及將一併刪除的**專案議題筆數**（零筆也要能刪）。確認後專案與其全部專案議題消失；取消則資料不變。 |

### PJ-F08：行事曆到期日視角加上專案／專案議題

| 項目 | 需求 |
|------|------|
| 功能目的 | 有預計完成日的專案與專案議題出現在首頁既有月曆，與正式議題到期日同一視角 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 行事曆「到期日」視角：除正式議題的預計完成日外，專案的預計完成日、專案議題的預計完成日也出現在對應日期格。點專案標記進入該專案詳情；點專案議題標記進入所屬專案詳情，並能辨識是哪一筆（捲動／展開該列或開啟該筆編輯，由 SA 定互動，但必須到達正確專案且使用者能對到該項次）。無預計完成日者不出現。預計開始日**不上**行事曆。 |

| 驗收條件 | 填了預計完成日的專案、專案議題出現在正確日期；改日期或刪除後月曆同步；到期日視角關掉時行為與第一階段對正式議題的視角規則一致（專案標記隨到期日視角顯示或隱藏）；點標記進入正確專案；預計項目視角不出現專案拖放。 |

# 五、角色權限

本輪只有**使用者本人**（單人、無登入）。

| 角色 | 可操作 |
|------|------|
| 使用者 | 本輪全部專案／專案議題畫面；既有分類設定、正式議題、TODO、首頁與行事曆 |
| 內部成員／客戶窗口 | 不是操作者；本輪無廠商或成員維護 |

無訪客、無管理員分流。任何人開到本機網站即擁有全部操作。

# 六、功能流程

跨功能主路徑（不重複第四章逐步操作）：

1. 使用者開啟網站 → 首頁（正式議題清單＋行事曆）或導覽進「專案」。
2. 新增專案（代號、名稱、分類、可填預計完成日）→ 出現在專案清單；若有預計完成日且行事曆到期日視角開啟，出現在該日。
3. 進入專案詳情 → 新增專案議題（項次、標題、分類、可填預計完成日）→ 列表出現；有預計完成日者同上曆。
4. 進度或完成：到分類設定準備小分類 → 回到專案或專案議題改**小分類**；清單與月曆色標更新。不改大分類當完成、不勾核取。
5. 刪單一專案議題 → 確認後該列與月曆標記消失，專案仍在。
6. 刪整個專案 → 確認（含議題筆數）→ 專案與全部專案議題、相關月曆標記消失。

後續階段才接入：Excel 匯入、廠商、工時、臨時工作、專案 TODO、正式議題綁專案、預約。

# 九、非功能需求

* **效能：** 單人使用；專案清單與單月行事曆在數百筆專案／專案議題加既有議題內應可於數秒內顯示。
* **安全性：** 仍無登入；不在畫面或儲存放入密鑰。
* **維護性：** 分類顏色仍集中既有設定；新頁面只重用第二階段 token，不另寫高飽和主色。
* **擴充性：** 專案議題以專案＋項次識別，利於之後 Excel 議題單；廠商與工時欄位本輪不預埋空殼也可於下階段加欄。
* **語系：** 使用者可見文案繁體中文。用詞：「專案」「專案議題」與「正式議題」須區隔，避免都叫「議題」而不標種類。
* **資料慣例：** 對齊 `AGENTS.md`：資料庫 snake_case、BIGINT 主鍵；C# 實體 PascalCase。
