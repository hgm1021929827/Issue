## 三、issue_todo（加欄）

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| project_id | 專案歸屬 | BIGINT | FK → project | 是 | NULL | 與 issue、work_item 恰一有值 |

C#：`IssueTodo.ProjectId`。

CHECK `ck_issue_todo_owner`：

```
(issue_id IS NOT NULL AND project_id IS NULL AND project_work_item_id IS NULL)
OR (issue_id IS NULL AND project_id IS NOT NULL AND project_work_item_id IS NULL)
OR (issue_id IS NULL AND project_id IS NULL AND project_work_item_id IS NOT NULL)
```

索引：`ix_issue_todo_project`（`project_id`, `parent_todo_id`, `sort_order`）。

FK：`fk_issue_todo_project` → `project(project_id)`。MySQL `ON DELETE CASCADE`；SQL Server Restrict，刪專案前應用層先刪待辦。

既有列：`project_id` 為 NULL。

## 五、connection_appointment_item

| 欄位名稱 | 中文名稱 | 資料型態 | 驗證限制 | 是否允許 NULL | 預設值 | 說明 |
| -------- | -------- | -------- | -------- | ------------- | ------ | ---- |
| item_id | 主鍵 | BIGINT | PK、自增 | 否 | — | C# `ItemId` |
| connection_appointment_id | 所屬預約 | BIGINT | FK CASCADE | 否 | — | |
| issue_id | 正式議題 | BIGINT | FK Restrict | 是 | NULL | 三者恰一 |
| project_id | 專案 | BIGINT | FK Restrict | 是 | NULL | |
| todo_id | 一般 TODO | BIGINT | FK Restrict | 是 | NULL | 僅議題或專案待辦 |
| sort_order | 排列 | INT | | 否 | — | |

CHECK `ck_appointment_item_target`：三者恰一非空。

UNIQUE：`(connection_appointment_id, issue_id)`、`(connection_appointment_id, project_id)`、`(connection_appointment_id, todo_id)`（NULL 不擋多列；有值不可重複）。SQL Server 用 filtered unique。

索引：`ix_appointment_item_appointment`（`connection_appointment_id`, `sort_order`）。

## 六、遷移注意

Seeder：先加 `issue_todo.project_id`、DROP/ADD CHECK，再建兩新表。EF `EnsureCreated` 新庫直接含三承載與兩表。SQL Server 不設預約事項對議題／專案 CASCADE，避免多重路徑。
