# 三、流程

1. 專案內容 tab：`GET /projects/{id}/todos`；新增 `POST` 同路徑。
2. 狀態選單：`GET /categories/appointment-status`；找不到「預約」則 `majorCategoryId` 空，表單提示不可存。
3. 新增預約：填表 → `GET /appointments/future?clientCompanyId=` → 無候選則 `POST /appointments`；有則 dialog。再新增走 POST；加入既有走 `POST /appointments/{id}/items`。
4. 編輯表頭 `PUT /appointments/{id}`；事項增刪走 items API。
5. 行事曆：既有 `GET /issues/calendar` 增量 `source=appointment`。

# 四、API

統一 `{ code, message, data }`。`code === 200` 成功。

| 方法 | 路徑 | Body | `data` |
|------|------|------|--------|
| GET/POST | `/projects/{projectId}/todos` | POST `{ parentId?, title, content? }` | `TodoNode[]` |
| GET | `/categories/appointment-status` | — | `{ majorCategoryId, name, color, subCategories[] }` |
| GET | `/appointments` | — | `Appointment[]` |
| GET | `/appointments/future?clientCompanyId=&excludeId=` | — | `Appointment[]` 未結束且日期晚於今天 |
| GET/PUT/DELETE | `/appointments/{id}` | PUT 表頭欄位 | 單筆或刪除 `{ deleted }` |
| POST | `/appointments` | `{ clientCompanyId, clientContactId, subCategoryId?, appointmentDate?, items? }` | 單筆 |
| POST | `/appointments/{id}/items` | `{ issueId? , projectId?, todoId? }` 或陣列 | 單筆 |
| DELETE | `/appointments/{id}/items/{itemId}` | — | 單筆 |

`TodoNode` 加 `projectId`；三者恰一有值。

`Appointment`：`id, clientCompanyId, clientCompanyName, clientContactId, clientContactName, subCategoryId, statusName, statusColor, appointmentDate, items[], itemSummary, createdAt, updatedAt`。

`AppointmentItem`：`id, kind`（`issue`／`project`／`todo`）、對應 id、`workLabel`、`title`、`content`、`children`（TODO 子樹，供展開）。

錯誤：404 找不到；400 未設廠商／窗口不符公司／處理事項種類不合法／找不到預約大分類而仍要存狀態；409 重複事項、使用中不可刪、跨層排序。

結束判定：狀態名稱 trim 後忽略大小寫等於「連線完成」或「連線取消」。空白未結束。未來＝`appointmentDate > 今天`。
