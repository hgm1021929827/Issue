# 二、模組拆分

| 模組 | 職責 |
|------|------|
| 專案詳情頁 | 已儲存時以 tab 切 `content`／`items` |
| 專案新增頁 | 不變，無 tab |
| 跳轉 | 既有 query 決定初始 tab |

# 三、功能流程

- `isNew === true`：現況單一表單。
- 已儲存：頁面標題（`專案 {code}`）在 tab 之上。`role="tablist"` 兩個 `role="tab"`：文案「專案內容」「專案議題」；議題 tab 可附 `（{items.length}）`。
- `tab === "content"`：專案表單（儲存／刪除）＋專案層 `TrackTodoList`。
- `tab === "items"`：專案議題列表＋新增；`AppDialog` 編輯流程不變。
- 切換 tab 不重置 `form`／`items`／`tracks`。
- 初始：`item` query 有值 → `items`，否則 `content`。專案 `id` 變更時依當下 query 重設。之後若 `item` 從無到有（同頁 query 變化）→ 切到 `items`。
- 僅 `trackTodo`、無 `item`：`content`；`TrackTodoList` `highlightId={!highlightId ? highlightTrackId : null}` 維持第五階段。
- `item` 找不到：既有橫幅「找不到該專案議題」，專案仍開；tab 仍為 `items`。

# 六、前端元件

| 區塊 | 行為 |
|------|------|
| 分頁列 | 與成員頁相同的 `chip`；`aria-selected` 對應當前 tab |
| 表單 | 已儲存且 `content` 時顯示；標題改放 tab 外，避免議題 tab 看不到專案代號 |
| 議題區 | 僅 `items` tab 顯示；dialog 仍掛在頁面層（切 tab 不卸載 dialog 若正在編輯——若 dialog 開著而使用者切回內容 tab，dialog 可維持開直到關閉，避免編到一半被拆掉） |

對話框開著時切 tab：dialog 為 portal，保持開啟；列表區塊可隱藏。關閉 dialog 規則不變。
