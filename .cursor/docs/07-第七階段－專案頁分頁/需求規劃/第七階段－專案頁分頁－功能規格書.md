# 一、專案介紹

專案詳情目前把專案表單、專案追蹤 TODO、專案議題列表疊在同一頁，議題區被擠在下方。本階段用兩個 tab 把「專案本身」與「底下的專案議題」分開看。

# 二、專案目標

1. 已儲存專案可用 tab 切換專案內容與專案議題，同一時間只展示其中一塊，減少捲動與擁擠。
2. 從首頁／行事曆跳進來時，該看議題就落到議題 tab，該看專案追蹤就留在內容 tab。
3. 專案與專案議題的資料行為與第三、四、五、七階段相同。

# 四、功能需求

### PT-F01：專案詳情兩個 tab

| 項目 | 需求 |
|------|------|
| 功能目的 | 把專案資料與專案議題分開，讓議題列表有完整空間 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 開啟已儲存專案，標題下看到「專案內容」「專案議題」兩個分頁（議題側可顯示目前筆數）。點選後只顯示該塊。切換不丟尚未儲存的專案表單內容。 |
| 功能限制 | 新增專案頁沒有這兩個 tab。專案清單頁不變。 |
| 注意事項 | 文案固定「專案內容」「專案議題」。專案內容含儲存、刪除專案、專案層追蹤 TODO。 |
| 驗收條件 | 已儲存專案可切換；同一時間看不到另一塊的主內容；新增專案仍是單表單。 |

### PT-F02：專案議題操作仍在議題 tab

| 項目 | 需求 |
|------|------|
| 功能目的 | 在議題 tab 專心管理項次 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | 在「專案議題」新增、點列編輯、刪除，行為與現況相同（`dialog`、確認刪除）。空列表仍提示尚無專案議題。 |
| 功能限制 | 不把專案議題改到獨立 URL（仍是 `/projects/{id}`）。 |
| 注意事項 | 項次追蹤 TODO 仍在編輯 dialog 內。 |
| 驗收條件 | 議題 CRUD 與第五／七階段追蹤在 dialog 內仍可用。 |

### PT-F03：跳轉自動選 tab

| 項目 | 需求 |
|------|------|
| 功能目的 | 從外部進來不必再自己找區塊 |
| 優先級 | Must |
| 是否本輪 MVP | 是 |
| 使用流程 | `/projects/{id}?item={workId}`（可再加 `trackTodo`）進入後落在「專案議題」，並列高亮、開編輯（既有）。只有 `trackTodo`、沒有 `item` 時落在「專案內容」並定位專案層追蹤。找不到項次時仍開專案，橫幅「找不到該專案議題」。 |
| 功能限制 | 不新增第三種 query 專門表示 tab。 |
| 注意事項 | 與第五、七階段跳轉路徑相容。 |
| 驗收條件 | 月曆／首頁點專案議題會開議題 tab；點專案層追蹤開內容 tab。 |

# 五、角色權限

單人、無登入；與既有專案頁相同。

# 六、功能流程

開啟已儲存專案 → 預設內容 tab → 可改資料並儲存，或切到議題 tab 管理項次。從月曆帶 `item` 進來則先落議題 tab 再開 dialog。刪專案仍只在內容 tab 操作。

# 七、資料需求

**本功能無 Database 持久化，第七章 Database 項目 N/A。**

分頁選擇僅畫面狀態；不寫入資料庫、不新增本機儲存需求。專案與專案議題資料沿用既有 API。
